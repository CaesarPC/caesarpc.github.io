HTTPS與網站安全實戰

CaesarTools 技術文章 · 2026-10-15

一、為什麼必須上HTTPS

HTTP是明文傳輸，你登錄網站輸入的密碼，中間經過的每一個路由器都能看到。2024年Chrome和Firefox對所有HTTP網站直接標"不安全"紅色警告，搜索引擎也把HTTPS作為排名信號，支付接口和Cookie的Secure屬性更是強制要求HTTPS。不上HTTPS基本等於沒法做正經網站。

二、免費SSL證書怎麼申請

Let's Encrypt提供完全免費的SSL證書，三個月有效期，自動續期。用Certbot工具一鍵配置：

sudo certbot --nginx -d example.com -d www.example.com

Certbot會自動改Nginx配置文件，自動申請證書，自動配置HTTPS跳轉。跑完就能用。三個月後它自己會續期，不用人管。

三、OWASP十大安全風險要防什麼

3.1 SQL注入

用戶輸入直接拼SQL字符串："SELECT * FROM users WHERE id = " + req.query.id。攻擊者傳id=1;DROP TABLE users;，你的庫就沒了。解法永遠是參數化查詢：pool.query('SELECT * FROM users WHERE id = $1', [id])。

3.2 XSS跨站腳本

用戶評論裡寫，其他用戶訪問時腳本就在瀏覽器裡跑了。解法：輸出到HTML時轉義特殊字符。React默認轉義，v-html要特別小心。CSP響應頭限制腳本來源。

3.3 CSRF跨站請求僞造

用戶登錄你的網站，同時訪問惡意網站，惡意網站偷偷發請求到你的後端，帶着用戶Cookie。解法：CSRF Token、SameSite Cookie、驗證Referer頭。

3.4 敏感數據泄露

密碼絕對不能明文存數據庫。用bcrypt哈希，bcrypt自帶salt，計算慢，抗暴力破解。數據庫被拖庫，攻擊者拿到的也是哈希值。

四、安全響應頭

Nginx配置加幾個頭，擋住大部分攻擊：

add_header X-Frame-Options DENY;

add_header X-Content-Type-Options nosniff;

add_header Strict-Transport-Security "max-age=31536000";

add_header Content-Security-Policy "default-src 'self'";

X-Frame-Options防止別人iframe嵌套你的頁面做點擊劫持。HSTS強制瀏覽器以後都用HTTPS訪問。CSP限制腳本只能從自己域名加載。

五、CORS跨域配置

不要直接寫Access-Control-Allow-Origin: *。生產環境指定具體域名：

app.use(cors({

origin: 'https://example.com',

credentials: true

}));

六、密鑰管理

數據庫密碼、JWT密鑰、第三方API Key不要寫代碼裡。用環境變量：

DATABASE_URL=postgres://...

JWT_SECRET=隨機長字符串

.gitignore文件要把.env排除。一旦密鑰提交到GitHub公開倉庫，立刻刪、換密鑰、改歷史。

七、登錄接口防護

登錄是攻擊重災區。加三道防線：失敗5次鎖賬號10分鐘；圖形驗證碼或滑塊防爆破；日誌記錄異常IP，批量失敗的IP直接封。JWT有效期設15分鐘，泄露了影響也小。

八、依賴安全

npm audit掃描已知漏洞。重要項目用lock文件鎖版本。GitHub Dependabot自動提PR修依賴漏洞。

九、常見漏項

後台管理地址/admin不做IP白名單，被爆破。上傳接口不校驗文件類型，傳個webshell上去。錯誤信息把堆棧返回給用戶，泄露數據庫結構。日誌裡打印密碼。這些都是新手常犯的錯。

十、總結

網站安全不是一次配置就完事。HTTPS是基礎，SQL注入/XSS/CSRF要從代碼層防，密碼哈希、密鑰管理、安全響應頭、CORS配置一套配齊。安全是持續工程，不是一次性項目。
