WebSocket實時通信實戰（3）

CaesarTools 技術文章 · 2026-10-15

一、HTTP和WebSocket區別

HTTP請求響應，一次請求一次響應。服務器不能主動推數據。要做實時聊天，前端要每秒輪詢一次，浪費。

WebSocket建立連接後一直保持，服務器可以主動推消息給前端。雙向通信，實時聊天、實時股價、協同編輯都用它。

二、基本用法

// 前端

const ws = new WebSocket('wss://example.com/chat');

ws.onopen = () => ws.send('你好');

ws.onmessage = (e) => console.log('收到:', e.data);

// Node後端

const WebSocket = require('ws');

const server = new WebSocket.Server({ port: 8080 });

server.on('connection', (socket) => {

socket.on('message', (msg) => {

console.log('收到:', msg);

socket.send('已收到');

});

});

三、心跳保活

連接可能斷。前端每30秒發ping，後端回pong。沒收到pong就重連。

四、生產部署

Nginx反向代理WebSocket要配Upgrade頭。

wss://加密，不能用ws://。

斷開自動重連。

五、常見坑

WebSocket連接數限制，單機幾萬要擴容。

消息順序保證。

不要傳太大消息，分片。

六、什麼時候用輪詢

實時性要求不高，5秒更新一次夠，用輪詢簡單。實時聊天用WebSocket。

七、總結

WebSocket是雙向實時通信。聊天、股價、協同編輯。心跳保活、自動重連、Nginx配置Upgrade。
