WebSocket實戰：實時通信從入門到生產

CaesarTools 技術文章 · 2026-10-15

一、HTTP和WebSocket的區別

HTTP是請求-響應模式：客戶端問，服務器答，答完連接關了。服務器想主動推消息給客戶端？做不到，只能靠輪詢。

WebSocket是全雙工通信：建立連接後，客戶端和服務器隨時互相發消息。聊天、通知、實時數據看板都需要這個。

二、什麼時候用WebSocket

- 在線聊天

- 實時通知（新訂單、新消息）

- 多人協作（文檔編輯）

- 實時數據看板（股票、監控）

三、基本用法

前端：

const ws = new WebSocket('wss://example.com/ws');

ws.onopen = () => ws.send('hello');

ws.onmessage = (e) => console.log(e.data);

ws.onclose = () => reconnect();

後端Node：

const WebSocket = require('ws');

const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', (ws) => {

ws.on('message', (data) => ws.send('收到: ' + data));

});

四、心跳保活

連接可能被中間網關掐斷（空閒30秒）。客戶端每隔30秒發ping，服務器回pong。多久沒收到pong就重連。

五、自動重連

連接斷了自動重連，指數退避：1秒、2秒、4秒、8秒，最多30秒。不要瘋狂重連打掛服務器。

六、生產注意事項

6.1 Nginx配置

WebSocket需要Upgrade頭：

proxy_set_header Upgrade $http_upgrade;

proxy_set_header Connection "upgrade";

6.2 鑑權

連接時帶token：new WebSocket('wss://...?token=xxx')。服務器驗證token。

6.3 集群

多臺Node實例，用戶連在不同實例上。用Redis Pub/Sub廣播消息。

七、Socket.io

Socket.io封裝了WebSocket，自動降級到長輪詢，帶重連和房間功能。新手推薦用。

八、常見坑

坑1：Nginx沒配Upgrade頭，連接握手失敗。

坑2：沒心跳，連接空閒被掐。

坑3：重連太頻繁，雪崩。

坑4：消息格式不統一，解析報錯。

九、SSE和WebSocket怎麼選

SSE（Server-Sent Events）是服務器單向推送，客戶端用普通HTTP接收。比WebSocket簡單，自動重連。適合只需要服務器推（通知、股票行情）的場景。WebSocket雙向通信，適合聊天。

十、總結

WebSocket是實時通信標配。前端建立連接、心跳保活、自動重連。後端Nginx配Upgrade、集群用Redis廣播。做好這幾點，實時應用就穩了。
