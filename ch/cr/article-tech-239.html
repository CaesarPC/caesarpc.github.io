# 事件委託：少綁定監聽器的性能技巧

一個列表有1000條數據，每條都有一個刪除按鈕。你給每個按鈕都綁定一個click事件監聽器——1000個監聽器，內存佔用大，新加的列表項還得重新綁定。事件委託用一個監聽器搞定所有按鈕。

## 一、原理

事件會冒泡：子元素上的事件會一層層往父元素傳播。你不在每個按鈕上綁監聽，而是在它們的共同父元素（比如ul）上綁一個。點擊按鈕時，事件冒泡到ul，在處理函數里判斷event.target是哪個按鈕，執行對應操作。

document.querySelector('ul').addEventListener('click', function(e) { if (e.target.tagName === 'BUTTON') { const id = e.target.dataset.id; deleteItem(id); } });

不管列表裡有10個還是10000個按鈕，只綁了一個監聽器。新加的按鈕自動支持，不需要重新綁定。

## 二、好處

性能好：一個監聽器 vs 一千個。 動態元素友好：新加的列表項自動有事件，不用手動綁定。 代碼簡潔：事件處理集中在一處。

## 三、注意

判斷event.target時要小心——按鈕裡面可能有圖標、span等子元素。點擊圖標時target是img不是button。解決辦法：用closest()向上找最近的匹配元素：e.target.closest('button')。

## 四、總結

事件委託是利用事件冒泡的經典優化。列表、表格這種動態生成大量相似元素的場景，用一個父級監聽器搞定所有子元素的事件，性能好又省心。
