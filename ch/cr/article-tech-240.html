# 防抖與節流：高頻事件的性能控制

搜索框每輸入一個字符就發一次API請求？滾動事件每幀觸發幾十次？鼠標移動事件更瘋狂——一秒鐘觸發上百次。如果每次都執行復雜邏輯，頁面直接卡死。防抖和節流是控制高頻事件執行頻率的兩種經典方案。

## 一、防抖（Debounce）

防抖的思路：事件觸發後等待一段時間再執行，如果在這段時間內又觸發了，就重新計時。直到用戶停下來不操作了，才真正執行。

搜索框聯想就是最典型的防抖場景。用戶連續輸入"JavaScript"，每次按鍵都發請求太浪費。防抖後：用戶停手300毫秒後才發一次請求，查完整的輸入。

function debounce(fn, delay) { let timer; return function(...args) { clearTimeout(timer); timer = setTimeout(() => fn.apply(this, args), delay); }; }

## 二、節流（Throttle）

節流的思路：不管事件觸發多頻繁，在固定時間間隔內只執行一次。比如每200毫秒最多執行一次。

滾動事件適合節流。用戶滾動頁面時，scroll事件瘋狂觸發，但你不需要每幀都做處理。節流保證每200毫秒執行一次滾動邏輯就夠了。

function throttle(fn, interval) { let last = 0; return function(...args) { const now = Date.now(); if (now - last >= interval) { last = now; fn.apply(this, args); } }; }

## 三、怎麼選

防抖：用戶停止操作後才執行一次。搜索輸入、窗口resize、表單驗證。 節流：固定頻率執行。滾動監聽、鼠標移動、拖拽。

## 四、總結

防抖和節流是前端處理高頻事件的標配工具。搜索用防抖，滾動用節流。現代框架（Lodash）都有現成的實現，直接用就行。但理解原理，知道什麼時候用哪個。
