BFF層：前後端之間的中間層

CaesarTools 技術文章 · 2026-10-15

一、為什麼需要BFF

前端開發經常遇到這種情況：首頁要顯示用戶信息、最近訂單、購物車數量、推薦商品。這四個數據分別來自四個後端服務。前端要發四個請求，等最慢的那個返回，頁面才能渲染。

BFF（Backend For Frontend）就是站在前端和後端服務之間的一層，專門給前端服務。前端只發一個請求到BFF，BFF去調用四個後端服務，聚合數據，組裝成前端需要的格式，一次返回。

二、BFF做什麼

聚合多個後端接口。前端發一次請求，BFF並行調用多個後端服務，一次返回全部數據。

裁剪字段。後端返回用戶10個字段，前端只要3個，BFF把多餘字段去掉。

協議轉換。後端用gRPC，前端用HTTP，BFF做轉換。

做緩存。重複請求直接命中BFF緩存，不打後端。

適配不同端。手機端字段少，桌面端字段多，BFF按設備返回不同數據。

三、怎麼實現

用Node.js寫一個服務：

const express = require('express');

const app = express();

app.get('/api/home', async (req, res) => {

const [user, orders, cart] = await Promise.all([

userService.getUser(),

orderService.getRecent(),

cartService.getCount()

]);

res.json({ user, orders, cart });

});

app.listen(3001);

前端請求http://api.example.com/api/home，一次拿到首頁全部數據。

四、BFF和GraphQL

GraphQL本質就是標準化的BFF查詢語言。前端聲明需要哪些字段，BFF（GraphQL Server）去後端取，只返回那些字段。

五、什麼時候不要BFF

簡單項目，一個後端服務就能搞定所有接口。不要為了用技術而用技術。BFF加了一層，也多了一個要維護的服務。

六、BFF的職責邊界

BFF只做數據聚合和裁剪，不要寫業務邏輯。業務邏輯在後端服務。BFF不要直接操作數據庫，它只是個轉發層。

七、常見坑

坑1：BFF寫了業務邏輯，和後端服務重複。

坑2：BFF緩存沒失效，數據和後端不一致。

坑3：BFF掛了，前端全站掛。要做高可用。

八、總結

BFF讓前端掌控數據組裝，減少請求次數，適配不同端。複雜項目值得加一層，簡單項目別過度設計。它是前後端協作的潤滑劑，不是銀彈。
