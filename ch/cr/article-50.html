CI/CD持續集成與部署

CaesarTools 技術文章 · 2026-10-15

一、什麼是CI/CD

CI持續集成：代碼push到倉庫後，自動跑測試、自動構建、自動檢查代碼質量。

CD持續部署：構建通過後，自動部署到生產環境。

沒有CI/CD：手動pull代碼、手動跑測試、手動build、手動部署到服務器。容易出錯，每次發佈要半小時。

有CI/CD：代碼push後，自動跑完所有流程，5分鐘部署完，出錯自動回滾。

二、GitHub Actions實戰

.github/workflows/deploy.yml：

name: Deploy

on:

push:

branches: [main]

jobs:

deploy:

runs-on: ubuntu-latest

steps:

- uses: actions/checkout@v4

- uses: actions/setup-node@v4

with:

node-version: 20

- run: npm ci

- run: npm test

- run: npm run build

- name: Deploy to server

uses: appleboy/ssh-action@master

with:

host: ${{ secrets.SSH_HOST }}

username: ${{ secrets.SSH_USER }}

key: ${{ secrets.SSH_KEY }}

script: |

cd /var/www/app

git pull

npm ci

pm2 restart app

三、常見階段

1. 代碼檢查：lint、類型檢查。

2. 跑測試：單元測試、集成測試。

3. 構建：build靜態文件或Docker鏡像。

4. 部署：SSH到服務器pull代碼重啟進程。

四、回滾

部署後發現bug，git revert上個提交，push觸發自動部署回滾。不要手動改生產代碼。

五、環境區分

開發環境develop分支自動部署到測試服務器。main分支手動確認後部署到生產。

六、常見坑

測試寫得少，CI只跑構建，bug到生產才發現。

環境變量沒配置，CI裡跑失敗。

部署腳本在本地能跑，CI裡權限不夠。

七、總結

CI/CD把發佈從手動半小時變成自動5分鐘。GitHub Actions免費額度夠小項目用。寫好流程，發佈不再是可怕的事。
