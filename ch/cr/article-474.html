CSS動畫與過渡實戰

CaesarTools 技術文章 · 2026-10-15

一、transition過渡

屬性變化時平滑過渡：

.button { transition: background 0.3s ease; }

.button:hover { background: blue; }

不要寫all，指定屬性性能好。

二、@keyframes動畫

@keyframes slide {

from { transform: translateX(-100%); }

to { transform: translateX(0); }

}

.animate { animation: slide 0.5s ease; }

三、性能原則

動畫只動transform和opacity。GPU合成，不觸發Layout和Paint。

動left/width每幀重排，掉幀。

四、will-change

提前告訴瀏覽器這個元素要動畫：

.will-animate { will-change: transform; }

不要濫用，佔額外顯存。

五、requestAnimationFrame

JS動畫跟着瀏覽器刷新節奏。setInterval不準。

function animate() {

el.style.transform = `translateX(${x}px)`;

requestAnimationFrame(animate);

}

六、常見坑

坑1：動畫改left/width掉幀。

坑2：will-change到處加顯存爆。

坑3：陰影+動畫同時Paint太貴。

坑4：同時太多動畫主線程忙。

七、DevTools檢查

Performance面板錄動畫。紫色Paint太長。FPS Meter看幀率。

八、硬件加速

transform和opacity讓瀏覽器給元素單獨開GPU圖層。過多圖層增加合成開銷。只有需要動畫的元素才開。

九、總結

CSS動畫性能核心：只動transform/opacity，GPU合成。JS用requestAnimationFrame。
