CI/CD持續集成與部署（2）

CaesarTools 技術文章 · 2026-10-15

一、為什麼需要CI/CD

手動部署：本地改代碼→git push→SSH登服務器→git pull→npm install→pm2 restart。每次部署手動操作，漏一步就出問題。團隊大了，誰改的、什麼時候部署的、部署出問題回滾到哪個版本，全靠聊天記錄翻。

CI/CD就是把這套流程自動化。代碼push到GitHub後，自動跑測試、自動打包、自動部署到服務器。出問題一鍵回滾。

二、GitHub Actions實戰

.github/workflows/deploy.yml：

name: Deploy

on:

push:

branches: [main]

jobs:

deploy:

runs-on: ubuntu-latest

steps:

- uses: actions/checkout@v3

- uses: actions/setup-node@v3

with:

node-version: 20

- run: npm ci

- run: npm test

- run: npm run build

- name: Deploy to server

uses: appleboy/ssh-action@v1

with:

host: ${{ secrets.SSH_HOST }}

username: ${{ secrets.SSH_USER }}

key: ${{ secrets.SSH_KEY }}

script: |

cd /var/www/app

git pull

npm ci --production

pm2 restart app

三、流程拆解

push代碼觸發。

自動跑npm test，測試不過阻止部署。

npm run build打包。

SSH到服務器，git pull，npm ci，pm2 restart。

四、關鍵原則

測試必須過才部署。

部署是自動化的，不靠人。

出問題一鍵回滾到上個版本。

日誌要記錄每次部署。

五、常見坑

測試寫得水，CI跑了等於沒跑。

服務器密碼放GitHub代碼裡，必須用secrets。

沒做回滾流程，部署出問題全站掛。

六、總結

CI/CD是工程成熟度標誌。代碼push自動測試自動部署，出問題一鍵回滾。
