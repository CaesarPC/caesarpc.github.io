JavaScript原型鏈完全指南

CaesarTools 技術文章 · 2026-10-15

一、JS為什麼需要原型鏈

Java是類繼承：先寫class，再new對象。JS一開始設計時沒有class（ES6才有），它用原型prototype實現繼承——對象之間直接關聯，一個對象的父類是另一個對象。

每個JS對象都有一個內部屬性[[Prototype]]（瀏覽器裡是__proto__），指向它的原型對象。訪問obj.prop時，obj自身沒有這個屬性，就順着__proto__往上找，一直找到null為止。這條鏈就是原型鏈。

二、一個對象的原型鏈長什麼樣

const arr = [1,2,3];

arr.push(4);

我們天天用push方法，但arr對象上並沒有push方法。arr.__proto__是Array.prototype，push就在那裡。arr.__proto__.__proto__是Object.prototype，toString則是在Object.prototype上找到的。Object.prototype.__proto__是null，到頭了。

三、constructor和prototype的關係

每個函數都有個prototype屬性，這個prototype對象有個constructor指回函數本身。

function Person(name) { this.name = name; }

Person.prototype.greet = function() { console.log(this.name); };

const p = new Person('小明');

p.__proto__ === Person.prototype;

p.constructor === Person;

new做了三件事：創建空對象、把對象__proto__指向構造函數prototype、執行構造函數綁定this。

四、ES6 class是語法糖

class Person {

constructor(name) { this.name = name; }

greet() { console.log(this.name); }

}

class只是上面原型寫法的語法糖，底層完全一樣。extends實現原型鏈繼承，super調用父類構造函數。現代項目用class更易讀，但要知道它底層還是原型鏈。

五、instanceof原理

obj instanceof Type：沿着obj的原型鏈找，看有沒有Type.prototype。[] instanceof Array為true，[] instanceof Object也為true，因為Array.prototype.__proto__是Object.prototype。

六、給內置類型擴展方法

Array.prototype.sum = function() { return this.reduce((a,b)=>a+b,0); };

[1,2,3].sum()返回6。但直接改內置原型有風險，未來JS可能加同名方法衝突。現代項目用工具函數更安全。

七、判斷類型

typeof對數組、null都返回object，不可靠。Object.prototype.toString.call([])返回[object Array]，這個方法判斷類型最準。

八、常見坑

坑1：for...in遍歷會把原型鏈上的可枚舉屬性帶出來。用hasOwnProperty過濾，或者用Object.keys。

坑2：改了prototype，所有實例立刻受影響。因為它們共享同一個原型對象。

坑3：__proto__不是標準API（雖然瀏覽器都實現）。生產代碼用Object.getPrototypeOf(obj)和Object.setPrototypeOf()。

坑4：原型鏈查找有性能成本。頻繁訪問深層原型屬性要考慮。

九、總結

原型鏈是JS繼承的根基。理解__proto__、prototype、constructor三者關係，知道屬性查找順序，class和extends就是紙上談兵。面試必考，工作中也處處在用——只是你用React或Vue框架時框架幫你包了一層。
