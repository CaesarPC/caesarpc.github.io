Nginx反向代理實戰（2）

CaesarTools 技術文章 · 2026-10-15

一、Nginx是網站大門

用戶訪問example.com，先到Nginx。Nginx決定：直接返回靜態文件？轉發給Node進程？轉發給哪個Node實例？它單機能抗5萬併發連接，而Node進程能處理幾百個併發就不錯了。學會Nginx是網站上線的最後一公里。

二、反向代理靜態站點

server {

listen 80;

root /var/www/dist;

index index.html;

location / {

try_files $uri $uri/ /index.html;

}

}

SPA單頁應用路由刷新404，try_files那行把所有請求fallback到index.html，讓前端路由處理。這一行是React/Vue部署的關鍵。

三、反向代理後端API

location /api/ {

proxy_pass http://127.0.0.1:3000;

proxy_set_header Host $host;

proxy_set_header X-Real-IP $remote_addr;

proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

}

/proxy_set_header把真實IP和域名透傳給後端，不然後端拿到的是Nginx的IP。

四、負載均衡多實例

upstream backend {

server 127.0.0.1:3000;

server 127.0.0.1:3001;

server 127.0.0.1:3002;

}

server {

location / {

proxy_pass http://backend;

}

}

三個Node實例輪詢分發。一個掛了自動踢掉。配合PM2 cluster模式，充分利用多核CPU。

五、HTTPS配置

server {

listen 443 ssl;

ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;

ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

location / {

proxy_pass http://127.0.0.1:3000;

}

}

server {

listen 80;

return 301 https://$host$request_uri;

}

80端口301跳轉到HTTPS。證書用Let's Encrypt免費籤。

六、靜態資源緩存

location ~* \.(js|css|png|jpg|woff2)$ {

expires 30d;

add_header Cache-Control "public";

}

靜態資源瀏覽器緩存30天，不用重複下載。帶hash文件名，更新自動刷新。

七、WebSocket支持

WebSocket需要Upgrade頭：

location /ws/ {

proxy_pass http://127.0.0.1:8080;

proxy_http_version 1.1;

proxy_set_header Upgrade $http_upgrade;

proxy_set_header Connection "upgrade";

}

不配這個頭，WebSocket握手直接失敗。

八、常見坑

大文件上傳client_max_body_size默認1MB，傳個10MB文件報413。調大到50M。改配置必須nginx -t測試再reload，不然改錯了整個網站掛。後端拿到的是Nginx IP，要配X-Forwarded-For透傳。

九、訪問日誌

Nginx默認日誌在/var/log/nginx/access.log。記錄每個請求的IP、路徑、狀態碼、耗時。排查問題先看日誌。

十、總結

Nginx做反向代理、負載均衡、HTTPS終止、靜態資源緩存。學會基礎配置，網站才算真正上線。
