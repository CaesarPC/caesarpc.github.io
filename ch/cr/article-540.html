前端測試入門：單元測試和E2E

CaesarTools 技術文章 · 2026-10-15

一、為什麼要寫測試

沒有測試的代碼，改一處不敢碰另一處。重構等於賭博。測試是給代碼上保險。

二、測試金字塔

底層：單元測試，多而快，測單個函數。

中層：集成測試，少而穩，測模塊配合。

頂層：E2E，最少最慢，模擬用戶操作。

大部分測試應該是單元測試。

三、單元測試

用Vitest或Jest：

function add(a, b) { return a + b; }

test('1+1=2', () => expect(add(1,1)).toBe(2));

覆蓋正常、邊界、異常。

四、組件測試

React用Testing Library：

render();

fireEvent.click(screen.getByText('+1'));

expect(screen.getByText('1')).toBeInTheDocument();

五、集成測試

測多個模塊配合。API用MSW mock。

六、E2E測試

Playwright或Cypress，真實瀏覽器模擬用戶。慢但最接近真實。

七、覆蓋率

80%參考線。不要為覆蓋率寫無意義測試。關鍵業務必須測。

八、CI裡跑測試

push後GitHub Actions自動跑。掛了阻止合併。

九、常見誤區

不寫測試遲早還債。

測試實現細節不測行為。

E2E寫太多維護貴。

mock過度等於沒測。

十、TDD

先寫測試再寫代碼。代碼天然可測。初期慢，長期省。

十一、測試和文檔

測試即文檔。看測試用例就知道函數怎麼用。比寫文檔省事，還能自動驗證。

十二、總結

測試是工程成熟度。單元測試主力，組件補充，E2E測關鍵流程。CI自動跑。
