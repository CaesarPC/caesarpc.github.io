JavaScript事件循環詳解：搞懂異步執行順序

CaesarTools 技術文章 · 2026-10-15

一、為什麼需要事件循環

JS是單線程語言——同一時間只能幹一件事。如果JS要等一個網絡請求返回，後面所有代碼都卡住，頁面就凍死了。

事件循環就是JS處理異步任務的機制：同步代碼立刻執行，異步任務掛起，等同步代碼跑完再回來處理。理解事件循環，你才能搞懂為什麼setTimeout有時候不準、Promise.then先於setTimeout執行。

二、事件循環基本流程

一個循環：

1. 執行棧裡的同步代碼

2. 清空微任務隊列

3. 渲染（如果需要）

4. 取一個宏任務執行

5. 回到第2步

關鍵：每執行完一個宏任務，都要清空所有微任務。微任務優先級高於宏任務。

三、微任務和宏任務

微任務：Promise.then、queueMicrotask、MutationObserver、process.nextTick(Node)。

宏任務：setTimeout、setInterval、setImmediate(Node)、I/O、UI事件。

微任務在當前宏任務結束後立刻執行，比下個宏任務早。

四、經典面試題

console.log(1);

setTimeout(() => console.log(2), 0);

Promise.resolve().then(() => console.log(3));

console.log(4);

輸出：1 4 3 2

分析：

- 同步代碼先跑：打印1、4

- 微任務Promise.then：打印3

- 宏任務setTimeout：打印2

五、為什麼setTimeout不準

setTimeout(fn, 0)不是0毫秒後執行。它是0毫秒後把fn放進宏任務隊列。如果隊列前面還有別的任務，fn要等。

Node官方規定setTimeout最低1毫秒。瀏覽器裡如果主線程忙，延遲幾十毫秒很正常。

六、async/await和事件循環

async function a() {

console.log(1);

await b();

console.log(2);

}

async function b() { console.log(3); }

console.log(4);

a();

console.log(5);

輸出：4 1 3 5 2

await後面的代碼相當於Promise.then，進微任務隊列。

七、長任務卡頓

主線程上一個任務超過50毫秒，用戶點擊就沒反應。這就是長任務。

解法：

- 大計算拆成小片，用scheduler.postTask

- 數據處理放Web Worker

- 虛擬滾動渲染長列表

八、Node和瀏覽器的區別

Node事件循環分階段：timers→pending callbacks→poll→check→close。setTimeout在timers階段，setImmediate在check階段。

瀏覽器沒有這些階段，就是宏任務+微任務簡單循環。

九、調試技巧

Chrome DevTools Performance面板錄一次操作，看火焰圖。黃色是腳本執行，紫色是渲染，綠色是Layout。紅色長條就是長任務。

十、生產中的事件循環問題

接口返回大量數據，前端遍歷處理10000條，主線程卡住200毫秒。用戶點按鈕沒反應。解法：把數據處理放Web Worker，主線程只負責渲染。

頁面滾動時觸發scroll事件，每次都計算位置。高頻事件用節流，減少主線程壓力。

十一、總結

事件循環：同步→微任務→渲染→宏任務，循環往復。微任務比宏任務先執行。懂了這個，JS異步順序就不會再亂。
