WebSocket實時通信實戰

CaesarTools 技術文章 · 2026-10-15

一、HTTP和WebSocket區別

HTTP請求-響應，答完連接關了。服務器想主動推消息做不到，只能輪詢。

WebSocket全雙工：建立連接後，雙方隨時互相發消息。聊天、通知、實時看板需要這個。

二、基本用法

前端：

const ws = new WebSocket('wss://example.com/ws');

ws.onopen = () => ws.send('hello');

ws.onmessage = (e) => console.log(e.data);

後端Node：

const WebSocket = require('ws');

const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', (ws) => {

ws.on('message', (data) => ws.send('收到: ' + data));

});

三、心跳保活

連接可能被中間網關掐斷。客戶端每30秒發ping，服務器回pong。多久沒收到就重連。

四、自動重連

連接斷了指數退避重連：1秒、2秒、4秒、8秒，最多30秒。不要瘋狂重連打掛服務器。

五、生產配置

Nginx配Upgrade頭。

連接時帶token鑑權。

多實例用Redis Pub/Sub廣播。

六、Socket.io

封裝WebSocket，自動降級長輪詢，帶重連和房間功能。新手推薦。

七、常見坑

Nginx沒配Upgrade頭握手失敗。

沒心跳連接被掐。

重連太頻繁雪崩。

八、SSE vs WebSocket

SSE服務器單向推送，簡單自動重連。通知、行情用SSE。聊天雙向用WebSocket。

九、消息格式

統一JSON格式：{type: 'chat', data: {...}}。前端按type分發處理。不要裸字符串，後期擴展麻煩。

十、總結

WebSocket實時通信標配。心跳保活、自動重連、Nginx配Upgrade、集群Redis廣播。
