前端狀態管理：從useState到Zustand

CaesarTools 技術文章 · 2026-10-15

一、狀態為什麼亂

組件多了，狀態到處放。A組件狀態B組件要用。prop一層層傳（prop drilling），代碼又臭又長。

狀態管理庫把共享狀態提到外面，任何組件直接讀寫。

二、React內置

useState組件本地狀態。

useContext跨層級傳狀態。

簡單場景夠用。

三、Redux

單向數據流：action→reducer→state→view。可預測，好調試。Redux DevTools時光旅行。但樣板代碼多。現代Redux Toolkit簡化了。

四、Zustand

極簡：const useStore = create((set) => ({ count: 0, inc: () => set(s => ({count: s.count+1})) }))。組件直接useStore()。

API簡單，體積小，新項目推薦。

五、TanStack Query

服務器狀態單獨管。緩存、後台刷新、失敗重試。不要把服務器數據塞Redux。

useQuery({ queryKey:['users'], queryFn:fetchUsers })。自動緩存。

六、什麼時候用什麼

本地狀態useState。跨層級主題/用戶useContext。複雜客戶端狀態Zustand。服務器數據TanStack Query。大型企業Redux Toolkit。

七、常見坑

所有狀態塞一個store，拆成多個。

服務器數據塞客戶端store。

直接改state視圖不更新。

小項目不需要狀態庫。

八、客戶端狀態vs服務器狀態

客戶端狀態：UI開關、表單草稿，放Zustand。

服務器狀態：用戶數據、列表，放TanStack Query。

混在一起調試噩夢。

九、總結

狀態管理按場景選。本地useState，跨層級Context，複雜客戶端Zustand，服務器數據TanStack Query。
