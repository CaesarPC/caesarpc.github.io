Docker實戰：從Dockerfile到多階段構建

CaesarTools 技術文章 · 2026-10-15

一、Docker解決什麼

"在我電腦上能跑"。開發機Mac，測試Windows，生產Linux。Docker把應用和依賴打包成鏡像，任何機器跑起來一樣。

二、Dockerfile

FROM node:20-alpine

WORKDIR /app

COPY package*.json ./

RUN npm ci --production

COPY . .

EXPOSE 3000

CMD ["node", "app.js"]

三、層緩存

先COPY package.json再npm ci。依賴沒變就用緩存，不重新install。順序很重要。

四、.dockerignore

node_modules、.git、.env、dist不要打進鏡像。

五、多階段構建

前端項目構建產物不需要Node環境：

FROM node:20-alpine AS builder

COPY . .

RUN npm ci && npm run build

FROM nginx:alpine

COPY --from=builder /app/dist /usr/share/nginx/html

最終鏡像只有nginx+靜態文件，50MB。

六、docker-compose

多服務一鍵起：

services:

api:

build: .

db:

image: postgres:16

docker-compose up -d。

七、生產要點

不要root跑容器。

鏡像打版本標籤不用latest。

日誌輸出到stdout。

健康檢查HEALTHCHECK。

資源限制。

八、常見坑

容器裡監聽127.0.0.1，外部訪問不到。要監聽0.0.0.0。

容器重建數據丟失，數據庫掛volume。

鏡像大，用alpine和多階段。

九、CI/CD裡用Docker

push代碼→CI構建鏡像→推到Registry→生產服務器pull重啟。全自動發佈。鏡像保證環境一致。

十、總結

Docker是現代部署標配。寫好Dockerfile、層緩存、多階段構建、compose管理多服務。
