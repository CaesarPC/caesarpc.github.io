JavaScript原型鏈完全指南：理解繼承的底層機制

CaesarTools 技術文章 · 2026-10-15

一、JS為什麼需要原型鏈

Java先寫class再new對象。JS早期沒有class，用對象之間直接關聯實現繼承。每個對象有個內部屬性[[Prototype]]（瀏覽器裡__proto__），指向它的原型。訪問obj.prop時，obj自身沒有，就順着__proto__往上找，直到null。這條鏈就是原型鏈。

二、一個對象的原型鏈長什麼樣

const arr = [1,2,3];

arr.push(4);

arr對象上並沒有push方法。arr.__proto__是Array.prototype，push就在那裡。arr.__proto__.__proto__是Object.prototype，toString在那裡。Object.prototype.__proto__是null，到頭了。

三、constructor和prototype

每個函數有個prototype屬性，這個對象有個constructor指回函數。

function Person(name) { this.name = name; }

Person.prototype.greet = function() { console.log(this.name); };

const p = new Person('小明');

p.__proto__ === Person.prototype;

p.constructor === Person;

new做了三件事：創建空對象、__proto__指向構造函數prototype、執行構造函數綁定this。

四、ES6 class是語法糖

class Person {

constructor(name) { this.name = name; }

greet() { console.log(this.name); }

}

底層和原型寫法一樣。extends實現繼承，super調用父類。現代項目用class更易讀，但要知道它是語法糖。

五、instanceof

obj instanceof Type：沿obj原型鏈找Type.prototype。

[] instanceof Array // true

[] instanceof Object // true

六、常見坑

坑1：for...in把原型鏈可枚舉屬性帶出來。用hasOwnProperty過濾。

坑2：改prototype，所有實例立刻受影響。

坑3：__proto__不是標準API。用Object.getPrototypeOf()。

七、原型鏈查找性能

頻繁訪問深層原型屬性有性能成本。熱點方法應該在對象自身上，不要每次沿鏈找。V8引擎對常見原型鏈做了內聯緩存優化，但寫代碼時還是要注意。

八、總結

原型鏈是JS繼承根基。__proto__、prototype、constructor三者關係搞懂，class就是紙上談兵。
