JavaScript this指向完全指南（2）

CaesarTools 技術文章 · 2026-10-15

一、this為什麼難搞

同一個函數，調用方式不同，this完全不同：

function say() { console.log(this.name); }

const obj = { name: '小明', say };

obj.say(); // 小明

say(); // undefined（嚴格模式）

this不是在定義時綁定的，是在調用時確定的。這就是它難的原因。

二、四條規則按優先級

判斷this指向，按這個順序查：new綁定 > 顯式綁定 > 隱式綁定 > 默認綁定。從高到低，誰命中用誰。

三、逐個拆開看

3.1 默認綁定

function fn() { console.log(this); }

fn(); // 瀏覽器裡window，嚴格模式undefined

最普通的調用。

3.2 隱式綁定

const obj = { name: '小明', say: function() { console.log(this.name); } };

obj.say(); // 小明

調用時前面有對象，this就是這個對象。

坑：把方法賦值給變量再調用

const fn = obj.say;

fn(); // undefined 因為這是默認綁定

3.3 顯式綁定

function say(greeting) { console.log(greeting + this.name); }

const obj = { name: '小明' };

say.call(obj, '你好'); // 你好小明

say.apply(obj, ['你好']); // apply參數是數組

const bound = say.bind(obj, '你好');

bound(); // 永久綁定this

call和apply立刻執行，bind返回新函數永久綁定。

3.4 new綁定

function Person(name) { this.name = name; }

const p = new Person('小明');

// new時this指向新創建的p

new優先級最高，即使函數之前bind過，new也能覆蓋。

四、箭頭函數：沒有自己的this

箭頭函數不創建自己的this，它繼承定義時外層的this。

const obj = {

name: '小明',

say: function() {

const inner = () => console.log(this.name);

inner();

}

};

obj.say(); // 小明

inner是箭頭函數，this繼承say的this（也就是obj）。這就是React類組件事件處理要用箭頭函數bind的原因。

五、高頻實戰

回調函數this丟失：setTimeout(obj.say, 1000)，this是window。解法：setTimeout(() => obj.say(), 1000) 或 obj.say.bind(obj)。

數組方法裡this：[1,2,3].forEach(function() { console.log(this); }, obj)。第二個參數指定this。

六、判斷this的口訣

看函數是怎麼調用的：new fn()就是新對象；fn.call(obj)就是obj；obj.fn()就是obj；fn()就是全局。箭頭函數繼承外層。

七、常見坑

坑1：箭頭函數當對象方法，this不是對象。因為箭頭函數繼承外層模塊作用域。

坑2：回調函數里this容易丟，用箭頭函數或bind。

坑3：setTimeout裡this不是你以為的那個。

八、總結

this不是看函數定義，是看函數調用。記住四條優先級規則，再記住箭頭函數沒有自己的this，this問題就解決了八九成。寫React類組件時用箭頭函數屬性，Vue裡用箭頭函數回調，都是this規則的實際應用。
