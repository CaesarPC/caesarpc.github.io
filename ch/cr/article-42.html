前端狀態管理：為什麼要用Redux/Zustand

CaesarTools 技術文章 · 2026-10-15

一、為什麼需要狀態管理

React組件內部用useState。組件多了，狀態要在多個組件間共享。一個用戶登錄狀態，導航欄要顯示名字，頁面要判斷權限。一層層props傳，傳到第五層，代碼全是props drilling。

狀態管理庫就是建一個全局倉庫，任何組件都能讀寫，不用props傳。

二、三種狀態要分清

本地狀態：一個組件內部用，useState夠了。

共享狀態：多個組件用，比如用戶登錄信息。

服務器狀態：從後端拿的數據，用React Query或SWR，不要放Redux。

三、Zustand實戰

import { create } from 'zustand';

const useStore = create((set) => ({

user: null,

login: (user) => set({ user }),

logout: () => set({ user: null })

}));

function Navbar() {

const user = useStore(s => s.user);

return

{user?.name}
;

}

四、什麼時候不要用Redux

簡單項目，幾個組件共享狀態用Context就夠。Redux模板代碼多，小項目殺雞用牛刀。

五、React Query管服務器狀態

後端數據不要自己管理加載、緩存、錯誤。用React Query：

import { useQuery } from '@tanstack/react-query';

const { data, isLoading } = useQuery({ queryKey: ['user'], queryFn: fetchUser });

自動緩存、自動重試、自動過期。

六、常見坑

把所有數據塞全局。本地狀態留在組件裡。

服務器狀態放Redux，重複造輪子。

狀態更新直接改原對象，要用不可變更新。

七、總結

狀態管理解決跨組件共享。本地用useState，共享用Zustand，服務器數據用React Query。
