TypeScript從入門到實戰

CaesarTools 技術文章 · 2026-10-15

一、為什麼要用TypeScript

JavaScript是動態類型語言，沒有編譯期檢查。你寫了一個函數，傳參時傳錯類型，代碼跑到一半才報undefined is not a function。而且編輯器沒有類型提示，打一半不知道對象有哪些屬性，全靠記憶和文檔。

TypeScript在JS之上加了一層靜態類型系統。寫代碼時編輯器實時告訴你這裡應該傳什麼類型，編譯時把所有類型錯誤抓出來，最後編譯成普通JS跑在瀏覽器和Node上。2024年React和Vue官方新項目默認用TS，大型公司招前端JD上基本都要求TS。學它不是選擇題，是必做題。

二、基本類型註解

let name: string = "小明";

let age: number = 12;

let isActive: boolean = true;

let hobbies: string[] = ["投球", "笛子"];

let nothing: null = null;

聯合類型表示一個值可以是幾種類型之一：

let id: string | number;

id = "abc";

id = 123;

類型別名：

type ID = string | number;

let uid: ID;

三、接口和類型

interface User {

id: number;

name: string;

email?: string; // 可選屬性

readonly createdAt: Date; // 只讀

}

function createUser(name: string): User {

return {

id: 1,

name,

createdAt: new Date()

};

}

interface可以擴展：

interface Admin extends User {

permissions: string[];

}

type和interface區別：type能定義聯合類型和交叉類型，interface能繼承和聲明合併。實際項目大部分場景兩個都行。

四、函數類型

函數參數和返回值都要標類型：

function add(a: number, b: number): number {

return a + b;

}

函數類型本身：

type AddFn = (a: number, b: number) => number;

回調函數：

function fetchUser(id: number, callback: (user: User) => void): void {

// ...

}

五、泛型

泛型讓函數可以處理多種類型同時保持類型安全：

function first(arr: T[]): T | undefined {

return arr[0];

}

const n = first([1, 2, 3]); // n是number

泛型在React的useState、API響應數據裡到處用：

const [user, setUser] = useState(null);

六、從JS遷移到TS

老項目遷移不要一步到位。分步驟：先tsc --init開strict，把新寫的模塊用TS，老JS文件保留。用// @ts-check在JS文件裡獲得類型提示漸進遷移。不要一上來就寫any，any等於沒寫類型。

七、常見坑

坑1：濫用any。一時爽，類型檢查形同虛設。用unknown代替，它是類型安全的any。

坑2：類型斷言as。先判斷再斷言，不要直接as User。

坑3：開了strictNullChecks，所有可能為null的值要寫判空。

坑4：第三方庫沒類型聲明，裝@types/xxx，或者自己寫d.ts。

八、工具類型

Partial所有屬性變可選。

Required所有屬性必填。

Pick選幾個屬性。

Omit排除某個屬性。

九、總結

TS是JS的超集，加了靜態類型。從基本類型、接口、函數、泛型開始學，開strict模式，漸進遷移老項目。它會讓你寫代碼慢一點，但bug少一半，長期省時間。
