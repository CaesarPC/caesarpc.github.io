CI/CD自動化部署：從手動到一鍵上線

CaesarTools 技術文章 · 2026-10-15

一、手動發佈的痛

git pull→npm install→build→scp上傳→ssh重啟。15分鐘，容易出錯，半夜出問題爬起來。

CI/CD全自動：push代碼→自動測試→構建→部署。

二、GitHub Actions

.github/workflows/deploy.yml：

on:

push:

branches: [main]

jobs:

deploy:

runs-on: ubuntu-latest

steps:

- uses: actions/checkout@v4

- run: npm ci

- run: npm test

- run: npm run build

- run: scp -r dist user@server:/var/www

三、Secrets

SSH密鑰、數據庫密碼存GitHub Secrets，用${{ secrets.XXX }}引用。不寫代碼裡。

四、測試是關鍵

CI不跑測試等於沒CI。測試掛了阻止部署。壞代碼上不了生產。

五、回滾

git revert上個壞提交，push，自動重新部署。

六、常見坑

坑1：CI環境和生產不一致。用Docker。

坑2：secrets硬編碼。立刻換。

坑3：直接部署生產。先預發佈驗證。

七、藍綠和灰度

零停機發布：跑兩個版本，Nginx切流量到新版本，有問題切回。

灰度：先給1%用戶看新版本，觀察沒問題再全量。

八、總結

CI/CD是工程成熟度標誌。GitHub Actions半小時搭好，從此告別手動發佈。
