Nginx實戰：反向代理、負載均衡和緩存

CaesarTools 技術文章 · 2026-10-15

一、Nginx是網站大門

用戶訪問example.com，先到Nginx。Nginx決定：直接返回靜態文件？轉發給Node進程？轉發給哪個Node實例？它單機能抗5萬併發。

二、反向代理靜態站點

server {

listen 80;

root /var/www/dist;

index index.html;

location / { try_files $uri $uri/ /index.html; }

}

SPA路由刷新404，try_files全部fallback到index.html。

三、反向代理後端

location /api/ {

proxy_pass http://127.0.0.1:3000;

proxy_set_header Host $host;

proxy_set_header X-Real-IP $remote_addr;

}

透傳真實IP給後端。

四、負載均衡

upstream backend {

server 127.0.0.1:3000;

server 127.0.0.1:3001;

}

server { location / { proxy_pass http://backend; } }

多實例輪詢。一個掛了自動踢掉。

五、HTTPS

listen 443 ssl;

ssl_certificate /etc/letsencrypt/live/.../fullchain.pem;

ssl_certificate_key ...;

80端口301跳HTTPS。

六、靜態資源緩存

location ~* \.(js|css|png|jpg)$ {

expires 30d;

add_header Cache-Control "public";

}

七、常見坑

WebSocket要Upgrade頭。

大文件上傳client_max_body_size默認1MB，調大。

改配置nginx -t測試再reload。

後端拿到的是Nginx IP，要X-Forwarded-For透傳。

八、訪問日誌

Nginx默認日誌在/var/log/nginx/access.log。記錄每個請求的IP、路徑、狀態碼、耗時。排查問題先看日誌。

九、總結

Nginx做反向代理、負載均衡、HTTPS終止、靜態資源緩存。學會基礎配置，網站才算真正上線。
