Git團隊協作規範

CaesarTools 技術文章 · 2026-10-15

一、Git為什麼重要

多人協作沒有版本控制就是災難。Git分佈式，每臺電腦完整歷史，離線也能提交。

二、分支工作流

main永遠可部署。新功能開feature分支。開發完發PR，Review後合併。不直接push main。

三、提交信息

feat新功能、fix修bug、docs文檔、refactor重構。寫清楚做了什麼，不要寫"更新"。

四、衝突解決

兩人改同一行，手動保留正確部分，刪標記，add再commit。預防：小步提交、經常pull。

五、撤銷操作

git checkout -- file撤銷修改。

git reset HEAD file取消暫存。

git revert abc安全撤銷。

git reset --hard強制回退（危險）。

六、暫存

git stash收起來，切分支幹別的，pop恢復。

七、.gitignore

node_modules、.env、dist不提交。

八、常見坑

大文件不要git add。用LFS。

密鑰提交到公開倉庫，立刻換。

force push共享分支。

九、代碼Review

PR不是走形式。看邏輯、測試、命名。被Review不要覺得被針對。

十、回滾

git revert壞提交，push，自動重新部署。

十一、變基vs合併

main更新了，feature分支同步：merge產生合併提交，歷史分叉。rebase把提交挪到main後，歷史直線。rebase歷史乾淨，但不要在共享分支用。

十二、總結

Git是工程師基本功。分支工作流、規範提交、衝突解決、PR Review。工具簡單，難在習慣。
