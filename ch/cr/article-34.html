CSS動畫性能：讓頁面60幀絲滑

CaesarTools 技術文章 · 2026-10-15

一、為什麼動畫會卡

屏幕每秒刷新60次，每幀16.7毫秒。一幀裡瀏覽器要做Layout、Paint、Composite。超過16毫秒就掉幀。

動畫改width/left，每幀都觸發Layout+Paint，手機上必卡。改transform/opacity，只觸發Composite，GPU加速，60幀絲滑。

二、觸發瀏覽器工作的屬性

Layout（重排）：width、height、margin、padding、left、top、position、font-size。

Paint（重繪）：color、background、border、box-shadow、outline。

Composite（合成）：transform、opacity。

動畫只用transform和opacity。

三、transform

transform: translate/scale/rotate/skew。不影響佈局，GPU合成。

@keyframes slide {

from { transform: translateX(-100%); }

to { transform: translateX(0); }

}

四、will-change

提前告訴瀏覽器這個元素要動畫，瀏覽器提前優化：

.will-animate { will-change: transform; }

不要濫用，每個will-change佔額外顯存。

五、requestAnimationFrame

JS動畫用requestAnimationFrame，跟着瀏覽器刷新節奏。setInterval不準，可能掉幀。

function animate() {

element.style.transform = `translateX(${x}px)`;

requestAnimationFrame(animate);

}

六、長列表滾動

大數據列表不要全部渲染。虛擬滾動：只渲染可視區域，滾動時動態替換內容。

七、圖片懶加載

原生懶加載。圖片進視口才下載。首屏加載快。

八、常見坑

坑1：動畫改left/width，掉幀。

坑2：will-change到處加，顯存爆。

坑3：陰影+動畫同時，Paint太貴。

坑4：同時太多動畫，主線程忙不過來。

九、DevTools檢查

Performance面板錄一次動畫。紫色塊是Paint，太長就是Paint開銷大。綠色塊Layout。FPS Meter看幀率。

十、硬件加速

transform和opacity會讓瀏覽器給元素單獨開一個GPU圖層。過多圖層反而增加合成開銷。只有需要動畫的元素才開。

十一、總結

CSS動畫性能核心：只動transform/opacity，GPU合成。JS動畫用requestAnimationFrame。虛擬滾動處理長列表。做好這幾點，動畫絲滑不卡。
