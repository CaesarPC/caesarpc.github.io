AI模型部署：vLLM和量化實戰

CaesarTools 技術文章 · 2026-10-15

一、模型部署的挑戰

訓練好的模型是文件，用戶沒法用。部署就是包成API：發文字返回生成內容。推理喫GPU顯存，併發要高。

二、基礎方案

FastAPI + transformers：

@app.post("/generate")

def generate(prompt: str):

return model.generate(prompt)

簡單但併發低，一個請求推理其他排隊。

三、vLLM高併發

7B模型原生transformers每秒幾個請求。vLLM用PagedAttention，吞吐量提升10-20倍，顯存利用率從20%到90%。

python -m vllm.entrypoints.openai.api_server --model Qwen/Qwen2-7B

直接暴露OpenAI兼容接口。

四、量化

7B FP16要14GB顯存。INT4只要4GB，一張4090跑。

BitsAndBytesConfig(load_in_4bit=True)。精度略降，多數場景無感。

五、GPU選擇

7B INT4：RTX 4090 24GB。

7B FP16：A10G 24GB。

70B INT4：A100 80GB。

六、常見坑

模型加載慢，啟動後預熱。

顯存OOM，限制max_tokens。

併發低，用vLLM。

同步阻塞，用FastAPI異步。

七、和業務後端配合

AI服務獨立部署GPU機器，業務後端HTTP調用。不要塞一個進程。

八、監控

GPU利用率、顯存、推理延遲P99。低於30%浪費錢，高於90%加卡。

九、模型版本管理

多個版本模型，用環境變量MODEL_VERSION切換權重。A/B測試同時跑兩個版本，按流量比例分流。

十、總結

AI部署選vLLM、做量化、獨立部署、監控GPU。個人4090跑7B，企業A100跑70B。
