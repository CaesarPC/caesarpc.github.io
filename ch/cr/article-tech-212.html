# Nginx實戰：反向代理、負載均衡與靜態服務

Nginx是全世界使用最廣泛的Web服務器。超過三分之一的網站用Nginx做反向代理和負載均衡。它做靜態文件服務快得驚人，做反向代理配置靈活，做負載均衡能輕鬆扛住幾萬併發。但很多人對Nginx的印象還停留在"改改配置文件轉發一下請求"，沒有真正用起來它的強大功能。

## 一、Nginx是什麼

Nginx是一個高性能的HTTP服務器和反向代理服務器。它最初就是為了解決C10K問題（單臺服務器同時處理一萬個併發連接）而設計的。採用事件驅動的異步非阻塞架構，內存佔用小、併發能力強。

Nginx有兩個核心角色：作為Web服務器直接提供靜態文件；作為反向代理把請求轉發給後端應用服務器。

## 二、反向代理：請求的統一入口

反向代理是Nginx最常用的功能。用戶不直接訪問後端應用，而是訪問Nginx，Nginx根據規則把請求轉發給後端的某個服務。

最簡單的配置： server { listen 80; server_name example.com; location / { proxy_pass http://127.0.0.1:3000; } }

所有發往example.com的請求，都轉發到本機3000端口的Node.js服務。用戶不知道後端跑的是什麼、跑在幾臺機器上。

反向代理的好處：安全——後端應用不直接暴露公網，只監聽本地端口，外部只能通過Nginx訪問。統一入口——SSL終止、日誌記錄、訪問控制都在Nginx層做，後端應用不用管。

## 三、負載均衡：把流量分給多臺服務器

當一臺服務器扛不住流量了，就加幾臺，Nginx在前面做負載均衡，把請求平均分到多臺後端服務器。

upstream backend { server 192.168.1.1:3000; server 192.168.1.2:3000; server 192.168.1.3:3000; } server { location / { proxy_pass http://backend; } }

默認是輪詢——請求一個一個輪流分給三臺服務器。還可以配置權重（某臺機器性能好多分點流量）、ip_hash（同一個用戶固定訪問同一臺服務器，解決Session共享問題）。

## 四、靜態文件服務

Nginx做靜態文件服務的性能極高，直接從磁盤讀文件返回，不需要經過後端應用。

server { root /var/www/dist; location / { try_files $uri $uri/ /index.html; } }

把前端構建產物放在/var/www/dist目錄，Nginx直接對外提供訪問。try_files那行是SPA（單頁應用）的關鍵：先找文件，找不到就返回index.html，讓前端路由處理。

## 五、HTTPS與Gzip

Nginx配置HTTPS非常簡單：把證書文件路徑配上，listen 443 ssl就行。HTTP的80端口自動301跳轉到HTTPS。

Gzip壓縮也是Nginx一行配置開啟的：gzip on;。開啟後，文本類資源（HTML、CSS、JS）會被壓縮傳輸，體積縮小70%以上，加載速度大幅提升。

## 六、常用Location匹配

location /匹配所有路徑。 location /api/匹配以/api/開頭的路徑。 location ~ \.js$用正則匹配以.js結尾的請求。 = /精確匹配根路徑。

掌握這幾種匹配方式，就能靈活地把不同路徑的請求分發到不同的後端或者處理方式。

## 七、總結

Nginx不是什麼複雜的技術，但它是每個Web項目都要用到的基礎設施。反向代理、負載均衡、靜態服務、HTTPS終止、Gzip壓縮——這些是Nginx最常用的功能。配置文件寫多了就發現，它就是一套聲明式規則，理解了location匹配和proxy_pass的轉發邏輯，大部分場景都能搞定。
