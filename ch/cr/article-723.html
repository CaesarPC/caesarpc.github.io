Docker容器化部署實戰（3）

CaesarTools 技術文章 · 2026-10-15

一、Docker解決了什麼問題

"在我電腦上能跑"是每個程序員都聽過的吐槽。開發機Mac，測試Windows，生產Linux，環境不一致導致bug修不完。Docker把應用和它的依賴（Node版本、系統庫、環境變量）一起打包成一個鏡像。這個鏡像在任何裝了Docker的機器上跑起來都一模一樣。

二、寫一個Dockerfile

FROM node:20-alpine

WORKDIR /app

COPY package*.json ./

RUN npm ci --production

COPY . .

EXPOSE 3000

CMD ["node", "app.js"]

逐行解釋：FROM選基礎鏡像，alpine版體積小隻有100MB，比完整版node:20的1GB小10倍。WORKDIR設置工作目錄。先COPY package.json再npm ci，利用Docker層緩存——依賴沒變就不重新install。COPY . .把代碼拷進去。EXPOSE聲明端口。CMD容器啟動命令。

三、.dockerignore

node_modules、.git、.env、dist不要打進鏡像：

node_modules

.git

.env

dist

減小鏡像體積，避免本地node_modules覆蓋容器內的。

四、多階段構建

前端項目構建產物不需要Node環境：

FROM node:20-alpine AS builder

WORKDIR /app

COPY . .

RUN npm ci && npm run build

FROM nginx:alpine

COPY --from=builder /app/dist /usr/share/nginx/html

最終鏡像只有nginx加靜態文件，體積從1GB壓到50MB。

五、docker-compose多服務

一個項目要起Node API加PostgreSQL加Redis，手動docker run三個太麻煩。docker-compose.yml：

services:

api:

build: .

ports: ["3000:3000"]

environment:

DATABASE_URL: postgres://db:5432/myapp

db:

image: postgres:16

volumes: [pgdata:/var/lib/postgresql/data]

redis:

image: redis:alpine

docker-compose up -d一行命令起三個服務。volumes持久化數據庫數據，容器重建數據不丟。

六、生產部署要點

不要用root用戶跑容器，Dockerfile加USER node。鏡像要打版本標籤，不要用latest。日誌輸出到stdout/stderr讓Docker收集。健康檢查HEALTHCHECK。資源限制--memory、--cpus防止單個容器喫滿機器。

七、常見坑

容器裡進程監聽127.0.0.1，外部訪問不到。要監聽0.0.0.0。容器重建數據丟失，數據庫數據必須掛volume。鏡像體積大，用alpine基礎鏡像加頭階段構建。

八、CI/CD裡用Docker

代碼push到GitHub後，CI自動構建鏡像推到Registry，生產服務器pull新鏡像重啟。整個過程全自動，不用人登服務器。

九、Docker網絡

容器間通信用Docker Compose服務名當域名。db容器名連接postgres://db:5432。不需要寫IP，Docker內部DNS自動解析。

十、總結

Docker是現代部署標配。寫好Dockerfile、用好層緩存、多階段構建壓縮體積、docker-compose管理多服務，一套標準流程把應用穩定部署到任何雲服務器。
