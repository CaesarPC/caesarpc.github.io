# 前端模塊化：從script標籤到ES Module

早期JS沒有模塊系統，所有變量都掛在全局作用域。兩個文件聲明瞭同名變量，後加載的覆蓋先加載的——各種衝突。文件多了之後，加載順序也成了問題——A依賴B，B必須在A之前加載。模塊化就是為了解決這些問題。

## 一、IIFE與命名空間

最早的方案：用立即執行函數（IIFE）把代碼包起來，變量不外泄。(function() { var secret = '...'; window.myApp = { ... }; })();。把需要暴露的掛到全局對象上，內部變量私有。jQuery就是這麼做的。

但這只是權宜之計——文件加載順序還是要手動管，依賴關係不清晰。

## 二、CommonJS與AMD

Node.js用CommonJS：require引入模塊，module.exports導出。同步加載，適合服務端。

瀏覽器早期用AMD（RequireJS）：異步加載模塊，定義時聲明依賴。但語法繁瑣，現在基本沒人用了。

## 三、ES Module

ES6（2015）正式在語言層面加入了模塊系統：import和export。

// math.js export function add(a, b) { return a + b; } export const PI = 3.14;

// main.js import { add, PI } from './math.js';

或者默認導出： export default function() { ... } import myFunc from './myFunc.js';

ES Module是靜態的——import語句必須在頂層，不能寫在if裡。這讓打包工具可以靜態分析依賴樹，做Tree Shaking（刪除沒用到的導出）。現代瀏覽器和Node.js都原生支持ES Module。

## 四、打包工具

瀏覽器原生ES Module需要服務器支持，而且大量小文件請求慢。Vite/Webpack把所有模塊打包成少數幾個文件，配合Tree Shaking和代碼分割，既享受模塊化開發又有加載性能。

## 五、總結

模塊化的核心是：每個文件是獨立作用域，顯式導出需要暴露的，顯式導入需要依賴的。ES Module是現代標準，import/export語法簡潔。理解模塊化，前端工程化才有意義。
