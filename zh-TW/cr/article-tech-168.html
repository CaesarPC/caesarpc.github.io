CSS容器查詢：組件真正可複用的響應式方案

媒體查詢（@media）是根據屏幕寬度調整樣式，但它有個根本缺陷：它看的是整個視口寬度，不是組件所在容器的寬度。一個側邊欄組件放在寬屏幕的主內容區裡，和放在窄屏幕的彈出層裡，視口寬度一樣，但容器寬度完全不同。媒體查詢無法區分這兩種情況。容器查詢（Container Queries）解決了這個問題。

容器查詢的思路是：先定義一個"容器"元素，然後根據這個容器的寬度調整內部組件的樣式。不是看屏幕多寬，而是看組件的父容器多寬。這樣組件真正做到了"放在哪裡都能自適應"——在寬容器裡橫排佈局，在窄容器裡豎排堆疊。

用法很簡單：父元素設置container-type: inline-size，聲明它是一個容器；然後用@container規則，根據容器寬度寫樣式。比如@container (min-width: 400px) { .card { display: flex; } }，容器寬度超過400px時卡片變橫排，否則豎排。

這對組件庫開發是革命性的。以前寫一個卡片組件，你不知道它會被放在多寬的容器裡，只能寫死一種佈局。現在組件可以自己根據容器寬度調整：容器寬就多列排列，容器窄就單列堆疊。同一個組件，在頁面主區域和側邊欄裡自動適配不同佈局。

容器查詢和媒體查詢的配合：媒體查詢管全局佈局（整頁是單列還是雙欄），容器查詢管組件內部佈局（卡片是橫排還是豎排）。兩者結合，響應式設計從"頁面級"細化到"組件級"。

瀏覽器兼容性已經很好，主流瀏覽器都支持。這是CSS響應式的未來方向：從屏幕尺寸驅動，變成容器尺寸驅動。組件真正可複用，不再需要為不同容器寫不同版本。
