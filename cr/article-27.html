JavaScript事件循环详解：搞懂异步执行顺序

CaesarTools 技术文章 · 2026-10-15

一、为什么需要事件循环

JS是单线程语言——同一时间只能干一件事。如果JS要等一个网络请求返回，后面所有代码都卡住，页面就冻死了。

事件循环就是JS处理异步任务的机制：同步代码立刻执行，异步任务挂起，等同步代码跑完再回来处理。理解事件循环，你才能搞懂为什么setTimeout有时候不准、Promise.then先于setTimeout执行。

二、事件循环基本流程

一个循环：

1. 执行栈里的同步代码

2. 清空微任务队列

3. 渲染（如果需要）

4. 取一个宏任务执行

5. 回到第2步

关键：每执行完一个宏任务，都要清空所有微任务。微任务优先级高于宏任务。

三、微任务和宏任务

微任务：Promise.then、queueMicrotask、MutationObserver、process.nextTick(Node)。

宏任务：setTimeout、setInterval、setImmediate(Node)、I/O、UI事件。

微任务在当前宏任务结束后立刻执行，比下个宏任务早。

四、经典面试题

console.log(1);

setTimeout(() => console.log(2), 0);

Promise.resolve().then(() => console.log(3));

console.log(4);

输出：1 4 3 2

分析：

- 同步代码先跑：打印1、4

- 微任务Promise.then：打印3

- 宏任务setTimeout：打印2

五、为什么setTimeout不准

setTimeout(fn, 0)不是0毫秒后执行。它是0毫秒后把fn放进宏任务队列。如果队列前面还有别的任务，fn要等。

Node官方规定setTimeout最低1毫秒。浏览器里如果主线程忙，延迟几十毫秒很正常。

六、async/await和事件循环

async function a() {

console.log(1);

await b();

console.log(2);

}

async function b() { console.log(3); }

console.log(4);

a();

console.log(5);

输出：4 1 3 5 2

await后面的代码相当于Promise.then，进微任务队列。

七、长任务卡顿

主线程上一个任务超过50毫秒，用户点击就没反应。这就是长任务。

解法：

- 大计算拆成小片，用scheduler.postTask

- 数据处理放Web Worker

- 虚拟滚动渲染长列表

八、Node和浏览器的区别

Node事件循环分阶段：timers→pending callbacks→poll→check→close。setTimeout在timers阶段，setImmediate在check阶段。

浏览器没有这些阶段，就是宏任务+微任务简单循环。

九、调试技巧

Chrome DevTools Performance面板录一次操作，看火焰图。黄色是脚本执行，紫色是渲染，绿色是Layout。红色长条就是长任务。

十、生产中的事件循环问题

接口返回大量数据，前端遍历处理10000条，主线程卡住200毫秒。用户点按钮没反应。解法：把数据处理放Web Worker，主线程只负责渲染。

页面滚动时触发scroll事件，每次都计算位置。高频事件用节流，减少主线程压力。

十一、总结

事件循环：同步→微任务→渲染→宏任务，循环往复。微任务比宏任务先执行。懂了这个，JS异步顺序就不会再乱。
