Vite前端构建工具：为什么它取代了Webpack

CaesarTools 技术文章 · 2026-10-15 📅 2026-10-15

一、Webpack为什么慢

中型项目冷启动30秒，改一行等5秒。Webpack启动时递归打包所有模块，时间随项目规模线性增长。

Vite利用浏览器原生ESM和esbuild，启动300毫秒。

二、Vite为什么快

2.1 原生ESM

开发时不打包。浏览器请求哪个文件，Vite才处理哪个。项目从100模块变10000，启动时间不变。

2.2 esbuild预构建依赖

npm依赖用Go写的esbuild预打包，比JS打包器快10-100倍。node_modules缓存一次就好。

2.3 精确HMR

改一个文件，浏览器只重新请求那个模块。毫秒级反馈。

三、基本使用

npm create vite@latest my-app -- --template react

cd my-app && npm install && npm run dev

四、生产构建

npm run build用Rollup打包。代码压缩、tree-shaking、分包优化。

五、常用配置

server.proxy开发环境代理。

build.rollupOptions.output.manualChunks分包。

import.meta.env.VITE_xxx环境变量。

六、插件生态

@vitejs/plugin-react、plugin-vue。社区插件丰富。

七、常见坑

坑1：IE不支持ESM。用legacy插件。

坑2：老项目迁移Webpack成本高。

坑3：某些Webpack loader生态依赖要换Vite插件。

八、Vite 5新特性

环境变量类型提示、CSS构建优化、Dev Server改进。2024年新项目默认Vite 5。

九、总结

Vite用浏览器原生能力重新定义开发体验。启动快、HMR快、配置简单。新项目无脑选。
