Docker实战：从Dockerfile到多阶段构建

CaesarTools 技术文章 · 2026-10-15

一、Docker解决什么

"在我电脑上能跑"。开发机Mac，测试Windows，生产Linux。Docker把应用和依赖打包成镜像，任何机器跑起来一样。

二、Dockerfile

FROM node:20-alpine

WORKDIR /app

COPY package*.json ./

RUN npm ci --production

COPY . .

EXPOSE 3000

CMD ["node", "app.js"]

三、层缓存

先COPY package.json再npm ci。依赖没变就用缓存，不重新install。顺序很重要。

四、.dockerignore

node_modules、.git、.env、dist不要打进镜像。

五、多阶段构建

前端项目构建产物不需要Node环境：

FROM node:20-alpine AS builder

COPY . .

RUN npm ci && npm run build

FROM nginx:alpine

COPY --from=builder /app/dist /usr/share/nginx/html

最终镜像只有nginx+静态文件，50MB。

六、docker-compose

多服务一键起：

services:

api:

build: .

db:

image: postgres:16

docker-compose up -d。

七、生产要点

不要root跑容器。

镜像打版本标签不用latest。

日志输出到stdout。

健康检查HEALTHCHECK。

资源限制。

八、常见坑

容器里监听127.0.0.1，外部访问不到。要监听0.0.0.0。

容器重建数据丢失，数据库挂volume。

镜像大，用alpine和多阶段。

九、CI/CD里用Docker

push代码→CI构建镜像→推到Registry→生产服务器pull重启。全自动发布。镜像保证环境一致。

十、总结

Docker是现代部署标配。写好Dockerfile、层缓存、多阶段构建、compose管理多服务。
