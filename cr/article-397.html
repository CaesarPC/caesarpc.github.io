WebSocket实时通信实战

CaesarTools 技术文章 · 2026-10-15

一、HTTP和WebSocket区别

HTTP请求-响应，答完连接关了。服务器想主动推消息做不到，只能轮询。

WebSocket全双工：建立连接后，双方随时互相发消息。聊天、通知、实时看板需要这个。

二、基本用法

前端：

const ws = new WebSocket('wss://example.com/ws');

ws.onopen = () => ws.send('hello');

ws.onmessage = (e) => console.log(e.data);

后端Node：

const WebSocket = require('ws');

const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', (ws) => {

ws.on('message', (data) => ws.send('收到: ' + data));

});

三、心跳保活

连接可能被中间网关掐断。客户端每30秒发ping，服务器回pong。多久没收到就重连。

四、自动重连

连接断了指数退避重连：1秒、2秒、4秒、8秒，最多30秒。不要疯狂重连打挂服务器。

五、生产配置

Nginx配Upgrade头。

连接时带token鉴权。

多实例用Redis Pub/Sub广播。

六、Socket.io

封装WebSocket，自动降级长轮询，带重连和房间功能。新手推荐。

七、常见坑

Nginx没配Upgrade头握手失败。

没心跳连接被掐。

重连太频繁雪崩。

八、SSE vs WebSocket

SSE服务器单向推送，简单自动重连。通知、行情用SSE。聊天双向用WebSocket。

九、消息格式

统一JSON格式：{type: 'chat', data: {...}}。前端按type分发处理。不要裸字符串，后期扩展麻烦。

十、总结

WebSocket实时通信标配。心跳保活、自动重连、Nginx配Upgrade、集群Redis广播。
