前端测试入门：单元测试和E2E

CaesarTools 技术文章 · 2026-10-15

一、为什么要写测试

没有测试的代码，改一处不敢碰另一处。重构等于赌博。测试是给代码上保险。

二、测试金字塔

底层：单元测试，多而快，测单个函数。

中层：集成测试，少而稳，测模块配合。

顶层：E2E，最少最慢，模拟用户操作。

大部分测试应该是单元测试。

三、单元测试

用Vitest或Jest：

function add(a, b) { return a + b; }

test('1+1=2', () => expect(add(1,1)).toBe(2));

覆盖正常、边界、异常。

四、组件测试

React用Testing Library：

render();

fireEvent.click(screen.getByText('+1'));

expect(screen.getByText('1')).toBeInTheDocument();

五、集成测试

测多个模块配合。API用MSW mock。

六、E2E测试

Playwright或Cypress，真实浏览器模拟用户。慢但最接近真实。

七、覆盖率

80%参考线。不要为覆盖率写无意义测试。关键业务必须测。

八、CI里跑测试

push后GitHub Actions自动跑。挂了阻止合并。

九、常见误区

不写测试迟早还债。

测试实现细节不测行为。

E2E写太多维护贵。

mock过度等于没测。

十、TDD

先写测试再写代码。代码天然可测。初期慢，长期省。

十一、测试和文档

测试即文档。看测试用例就知道函数怎么用。比写文档省事，还能自动验证。

十二、总结

测试是工程成熟度。单元测试主力，组件补充，E2E测关键流程。CI自动跑。
