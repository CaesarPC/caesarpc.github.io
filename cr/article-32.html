WebSocket实战：实时通信从入门到生产

CaesarTools 技术文章 · 2026-10-15 📅 2026-10-15

一、HTTP和WebSocket的区别

HTTP是请求-响应模式：客户端问，服务器答，答完连接关了。服务器想主动推消息给客户端？做不到，只能靠轮询。

WebSocket是全双工通信：建立连接后，客户端和服务器随时互相发消息。聊天、通知、实时数据看板都需要这个。

二、什么时候用WebSocket

- 在线聊天

- 实时通知（新订单、新消息）

- 多人协作（文档编辑）

- 实时数据看板（股票、监控）

三、基本用法

前端：

const ws = new WebSocket('wss://example.com/ws');

ws.onopen = () => ws.send('hello');

ws.onmessage = (e) => console.log(e.data);

ws.onclose = () => reconnect();

后端Node：

const WebSocket = require('ws');

const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', (ws) => {

ws.on('message', (data) => ws.send('收到: ' + data));

});

四、心跳保活

连接可能被中间网关掐断（空闲30秒）。客户端每隔30秒发ping，服务器回pong。多久没收到pong就重连。

五、自动重连

连接断了自动重连，指数退避：1秒、2秒、4秒、8秒，最多30秒。不要疯狂重连打挂服务器。

六、生产注意事项

6.1 Nginx配置

WebSocket需要Upgrade头：

proxy_set_header Upgrade $http_upgrade;

proxy_set_header Connection "upgrade";

6.2 鉴权

连接时带token：new WebSocket('wss://...?token=xxx')。服务器验证token。

6.3 集群

多台Node实例，用户连在不同实例上。用Redis Pub/Sub广播消息。

七、Socket.io

Socket.io封装了WebSocket，自动降级到长轮询，带重连和房间功能。新手推荐用。

八、常见坑

坑1：Nginx没配Upgrade头，连接握手失败。

坑2：没心跳，连接空闲被掐。

坑3：重连太频繁，雪崩。

坑4：消息格式不统一，解析报错。

九、SSE和WebSocket怎么选

SSE（Server-Sent Events）是服务器单向推送，客户端用普通HTTP接收。比WebSocket简单，自动重连。适合只需要服务器推（通知、股票行情）的场景。WebSocket双向通信，适合聊天。

十、总结

WebSocket是实时通信标配。前端建立连接、心跳保活、自动重连。后端Nginx配Upgrade、集群用Redis广播。做好这几点，实时应用就稳了。
