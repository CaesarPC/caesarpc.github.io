BFF层：前后端之间的中间层

CaesarTools 技术文章 · 2026-10-15

一、为什么需要BFF

前端开发经常遇到这种情况：首页要显示用户信息、最近订单、购物车数量、推荐商品。这四个数据分别来自四个后端服务。前端要发四个请求，等最慢的那个返回，页面才能渲染。

BFF（Backend For Frontend）就是站在前端和后端服务之间的一层，专门给前端服务。前端只发一个请求到BFF，BFF去调用四个后端服务，聚合数据，组装成前端需要的格式，一次返回。

二、BFF做什么

聚合多个后端接口。前端发一次请求，BFF并行调用多个后端服务，一次返回全部数据。

裁剪字段。后端返回用户10个字段，前端只要3个，BFF把多余字段去掉。

协议转换。后端用gRPC，前端用HTTP，BFF做转换。

做缓存。重复请求直接命中BFF缓存，不打后端。

适配不同端。手机端字段少，桌面端字段多，BFF按设备返回不同数据。

三、怎么实现

用Node.js写一个服务：

const express = require('express');

const app = express();

app.get('/api/home', async (req, res) => {

const [user, orders, cart] = await Promise.all([

userService.getUser(),

orderService.getRecent(),

cartService.getCount()

]);

res.json({ user, orders, cart });

});

app.listen(3001);

前端请求http://api.example.com/api/home，一次拿到首页全部数据。

四、BFF和GraphQL

GraphQL本质就是标准化的BFF查询语言。前端声明需要哪些字段，BFF（GraphQL Server）去后端取，只返回那些字段。

五、什么时候不要BFF

简单项目，一个后端服务就能搞定所有接口。不要为了用技术而用技术。BFF加了一层，也多了一个要维护的服务。

六、BFF的职责边界

BFF只做数据聚合和裁剪，不要写业务逻辑。业务逻辑在后端服务。BFF不要直接操作数据库，它只是个转发层。

七、常见坑

坑1：BFF写了业务逻辑，和后端服务重复。

坑2：BFF缓存没失效，数据和后端不一致。

坑3：BFF挂了，前端全站挂。要做高可用。

八、总结

BFF让前端掌控数据组装，减少请求次数，适配不同端。复杂项目值得加一层，简单项目别过度设计。它是前后端协作的润滑剂，不是银弹。
