TypeScript实战：从类型定义到泛型

CaesarTools 技术文章 · 2026-10-15

一、JS的痛

JS动态类型，运行时才发现错。add(1,'2')返回"12"你以为是bug。大型项目改字段名，编译不报错，用户点击才崩。TS加静态类型，编译时抓错。

二、基本类型

let name: string = '小明';

let age: number = 18;

let hobbies: string[] = ['篮球'];

三、接口

interface User {

id: number;

name: string;

email?: string;

readonly createdAt: Date;

}

传错字段编译报错。

四、联合类型

type Status = 'pending' | 'success' | 'error';

比string精确。

五、泛型

function identity(arg: T): T { return arg; }

写通用函数不丢类型。useState(0)。

六、在React里用

interface Props { title: string; onClick: () => void; }

function Button({ title, onClick }: Props) { ... }

七、常见坑

坑1：any。写了any等于没写。开strict模式。

坑2：as强行断言。绕过检查出运行时错。

坑3：第三方库没类型。装@types/xxx。

八、类型推导

TS能自动推导类型，不用每个都标注。const count = 0推成number。函数返回值也能推。让TS自己推，只在边界（函数参数、公共API）标注。

九、总结

TS是JS加类型。大型项目、团队协作，编译期抓bug，重构有提示。新项目无脑TS。
