JavaScript this指向完全指南

CaesarTools 技术文章 · 2026-10-15

一、this为什么难搞

同一个函数，调用方式不同，this完全不同：

function say() { console.log(this.name); }

const obj = { name: '小明', say };

obj.say(); // 小明

say(); // undefined（严格模式）

this不是在定义时绑定的，是在调用时确定的。这就是它难的原因。

二、四条规则按优先级

判断this指向，按这个顺序查：new绑定 > 显式绑定 > 隐式绑定 > 默认绑定。从高到低，谁命中用谁。

三、逐个拆开看

3.1 默认绑定

function fn() { console.log(this); }

fn(); // 浏览器里window，严格模式undefined

最普通的调用。

3.2 隐式绑定

const obj = { name: '小明', say: function() { console.log(this.name); } };

obj.say(); // 小明

调用时前面有对象，this就是这个对象。

坑：把方法赋值给变量再调用

const fn = obj.say;

fn(); // undefined 因为这是默认绑定

3.3 显式绑定

function say(greeting) { console.log(greeting + this.name); }

const obj = { name: '小明' };

say.call(obj, '你好'); // 你好小明

say.apply(obj, ['你好']); // apply参数是数组

const bound = say.bind(obj, '你好');

bound(); // 永久绑定this

call和apply立刻执行，bind返回新函数永久绑定。

3.4 new绑定

function Person(name) { this.name = name; }

const p = new Person('小明');

// new时this指向新创建的p

new优先级最高，即使函数之前bind过，new也能覆盖。

四、箭头函数：没有自己的this

箭头函数不创建自己的this，它继承定义时外层的this。

const obj = {

name: '小明',

say: function() {

const inner = () => console.log(this.name);

inner();

}

};

obj.say(); // 小明

inner是箭头函数，this继承say的this（也就是obj）。这就是React类组件事件处理要用箭头函数bind的原因。

五、高频实战

回调函数this丢失：setTimeout(obj.say, 1000)，this是window。解法：setTimeout(() => obj.say(), 1000) 或 obj.say.bind(obj)。

数组方法里this：[1,2,3].forEach(function() { console.log(this); }, obj)。第二个参数指定this。

六、判断this的口诀

看函数是怎么调用的：new fn()就是新对象；fn.call(obj)就是obj；obj.fn()就是obj；fn()就是全局。箭头函数继承外层。

七、常见坑

坑1：箭头函数当对象方法，this不是对象。因为箭头函数继承外层模块作用域。

坑2：回调函数里this容易丢，用箭头函数或bind。

坑3：setTimeout里this不是你以为的那个。

八、总结

this不是看函数定义，是看函数调用。记住四条优先级规则，再记住箭头函数没有自己的this，this问题就解决了八九成。写React类组件时用箭头函数属性，Vue里用箭头函数回调，都是this规则的实际应用。
