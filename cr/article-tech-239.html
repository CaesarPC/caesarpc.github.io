# 事件委托：少绑定监听器的性能技巧

一个列表有1000条数据，每条都有一个删除按钮。你给每个按钮都绑定一个click事件监听器——1000个监听器，内存占用大，新加的列表项还得重新绑定。事件委托用一个监听器搞定所有按钮。

## 一、原理

事件会冒泡：子元素上的事件会一层层往父元素传播。你不在每个按钮上绑监听，而是在它们的共同父元素（比如ul）上绑一个。点击按钮时，事件冒泡到ul，在处理函数里判断event.target是哪个按钮，执行对应操作。

document.querySelector('ul').addEventListener('click', function(e) { if (e.target.tagName === 'BUTTON') { const id = e.target.dataset.id; deleteItem(id); } });

不管列表里有10个还是10000个按钮，只绑了一个监听器。新加的按钮自动支持，不需要重新绑定。

## 二、好处

性能好：一个监听器 vs 一千个。 动态元素友好：新加的列表项自动有事件，不用手动绑定。 代码简洁：事件处理集中在一处。

## 三、注意

判断event.target时要小心——按钮里面可能有图标、span等子元素。点击图标时target是img不是button。解决办法：用closest()向上找最近的匹配元素：e.target.closest('button')。

## 四、总结

事件委托是利用事件冒泡的经典优化。列表、表格这种动态生成大量相似元素的场景，用一个父级监听器搞定所有子元素的事件，性能好又省心。
