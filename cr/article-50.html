CI/CD持续集成与部署

CaesarTools 技术文章 · 2026-10-15

一、什么是CI/CD

CI持续集成：代码push到仓库后，自动跑测试、自动构建、自动检查代码质量。

CD持续部署：构建通过后，自动部署到生产环境。

没有CI/CD：手动pull代码、手动跑测试、手动build、手动部署到服务器。容易出错，每次发布要半小时。

有CI/CD：代码push后，自动跑完所有流程，5分钟部署完，出错自动回滚。

二、GitHub Actions实战

.github/workflows/deploy.yml：

name: Deploy

on:

push:

branches: [main]

jobs:

deploy:

runs-on: ubuntu-latest

steps:

- uses: actions/checkout@v4

- uses: actions/setup-node@v4

with:

node-version: 20

- run: npm ci

- run: npm test

- run: npm run build

- name: Deploy to server

uses: appleboy/ssh-action@master

with:

host: ${{ secrets.SSH_HOST }}

username: ${{ secrets.SSH_USER }}

key: ${{ secrets.SSH_KEY }}

script: |

cd /var/www/app

git pull

npm ci

pm2 restart app

三、常见阶段

1. 代码检查：lint、类型检查。

2. 跑测试：单元测试、集成测试。

3. 构建：build静态文件或Docker镜像。

4. 部署：SSH到服务器pull代码重启进程。

四、回滚

部署后发现bug，git revert上个提交，push触发自动部署回滚。不要手动改生产代码。

五、环境区分

开发环境develop分支自动部署到测试服务器。main分支手动确认后部署到生产。

六、常见坑

测试写得少，CI只跑构建，bug到生产才发现。

环境变量没配置，CI里跑失败。

部署脚本在本地能跑，CI里权限不够。

七、总结

CI/CD把发布从手动半小时变成自动5分钟。GitHub Actions免费额度够小项目用。写好流程，发布不再是可怕的事。
