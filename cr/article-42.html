前端状态管理：为什么要用Redux/Zustand

CaesarTools 技术文章 · 2026-10-15

一、为什么需要状态管理

React组件内部用useState。组件多了，状态要在多个组件间共享。一个用户登录状态，导航栏要显示名字，页面要判断权限。一层层props传，传到第五层，代码全是props drilling。

状态管理库就是建一个全局仓库，任何组件都能读写，不用props传。

二、三种状态要分清

本地状态：一个组件内部用，useState够了。

共享状态：多个组件用，比如用户登录信息。

服务器状态：从后端拿的数据，用React Query或SWR，不要放Redux。

三、Zustand实战

import { create } from 'zustand';

const useStore = create((set) => ({

user: null,

login: (user) => set({ user }),

logout: () => set({ user: null })

}));

function Navbar() {

const user = useStore(s => s.user);

return

{user?.name}
;

}

四、什么时候不要用Redux

简单项目，几个组件共享状态用Context就够。Redux模板代码多，小项目杀鸡用牛刀。

五、React Query管服务器状态

后端数据不要自己管理加载、缓存、错误。用React Query：

import { useQuery } from '@tanstack/react-query';

const { data, isLoading } = useQuery({ queryKey: ['user'], queryFn: fetchUser });

自动缓存、自动重试、自动过期。

六、常见坑

把所有数据塞全局。本地状态留在组件里。

服务器状态放Redux，重复造轮子。

状态更新直接改原对象，要用不可变更新。

七、总结

状态管理解决跨组件共享。本地用useState，共享用Zustand，服务器数据用React Query。
