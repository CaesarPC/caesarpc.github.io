JavaScript原型链完全指南

CaesarTools 技术文章 · 2026-10-15

一、JS为什么需要原型链

Java是类继承：先写class，再new对象。JS一开始设计时没有class（ES6才有），它用原型prototype实现继承——对象之间直接关联，一个对象的父类是另一个对象。

每个JS对象都有一个内部属性[[Prototype]]（浏览器里是__proto__），指向它的原型对象。访问obj.prop时，obj自身没有这个属性，就顺着__proto__往上找，一直找到null为止。这条链就是原型链。

二、一个对象的原型链长什么样

const arr = [1,2,3];

arr.push(4);

我们天天用push方法，但arr对象上并没有push方法。arr.__proto__是Array.prototype，push就在那里。arr.__proto__.__proto__是Object.prototype，toString则是在Object.prototype上找到的。Object.prototype.__proto__是null，到头了。

三、constructor和prototype的关系

每个函数都有个prototype属性，这个prototype对象有个constructor指回函数本身。

function Person(name) { this.name = name; }

Person.prototype.greet = function() { console.log(this.name); };

const p = new Person('小明');

p.__proto__ === Person.prototype;

p.constructor === Person;

new做了三件事：创建空对象、把对象__proto__指向构造函数prototype、执行构造函数绑定this。

四、ES6 class是语法糖

class Person {

constructor(name) { this.name = name; }

greet() { console.log(this.name); }

}

class只是上面原型写法的语法糖，底层完全一样。extends实现原型链继承，super调用父类构造函数。现代项目用class更易读，但要知道它底层还是原型链。

五、instanceof原理

obj instanceof Type：沿着obj的原型链找，看有没有Type.prototype。[] instanceof Array为true，[] instanceof Object也为true，因为Array.prototype.__proto__是Object.prototype。

六、给内置类型扩展方法

Array.prototype.sum = function() { return this.reduce((a,b)=>a+b,0); };

[1,2,3].sum()返回6。但直接改内置原型有风险，未来JS可能加同名方法冲突。现代项目用工具函数更安全。

七、判断类型

typeof对数组、null都返回object，不可靠。Object.prototype.toString.call([])返回[object Array]，这个方法判断类型最准。

八、常见坑

坑1：for...in遍历会把原型链上的可枚举属性带出来。用hasOwnProperty过滤，或者用Object.keys。

坑2：改了prototype，所有实例立刻受影响。因为它们共享同一个原型对象。

坑3：__proto__不是标准API（虽然浏览器都实现）。生产代码用Object.getPrototypeOf(obj)和Object.setPrototypeOf()。

坑4：原型链查找有性能成本。频繁访问深层原型属性要考虑。

九、总结

原型链是JS继承的根基。理解__proto__、prototype、constructor三者关系，知道属性查找顺序，class和extends就是纸上谈兵。面试必考，工作中也处处在用——只是你用React或Vue框架时框架帮你包了一层。
