Docker容器化部署实战

CaesarTools 技术文章 · 2026-10-15

一、Docker解决了什么问题

"在我电脑上能跑"是每个程序员都听过的吐槽。开发机Mac，测试Windows，生产Linux，环境不一致导致bug修不完。Docker把应用和它的依赖（Node版本、系统库、环境变量）一起打包成一个镜像。这个镜像在任何装了Docker的机器上跑起来都一模一样。

二、写一个Dockerfile

FROM node:20-alpine

WORKDIR /app

COPY package*.json ./

RUN npm ci --production

COPY . .

EXPOSE 3000

CMD ["node", "app.js"]

逐行解释：FROM选基础镜像，alpine版体积小只有100MB，比完整版node:20的1GB小10倍。WORKDIR设置工作目录。先COPY package.json再npm ci，利用Docker层缓存——依赖没变就不重新install。COPY . .把代码拷进去。EXPOSE声明端口。CMD容器启动命令。

三、.dockerignore

node_modules、.git、.env、dist不要打进镜像：

node_modules

.git

.env

dist

减小镜像体积，避免本地node_modules覆盖容器内的。

四、多阶段构建

前端项目构建产物不需要Node环境：

FROM node:20-alpine AS builder

WORKDIR /app

COPY . .

RUN npm ci && npm run build

FROM nginx:alpine

COPY --from=builder /app/dist /usr/share/nginx/html

最终镜像只有nginx加静态文件，体积从1GB压到50MB。

五、docker-compose多服务

一个项目要起Node API加PostgreSQL加Redis，手动docker run三个太麻烦。docker-compose.yml：

services:

api:

build: .

ports: ["3000:3000"]

environment:

DATABASE_URL: postgres://db:5432/myapp

db:

image: postgres:16

volumes: [pgdata:/var/lib/postgresql/data]

redis:

image: redis:alpine

docker-compose up -d一行命令起三个服务。volumes持久化数据库数据，容器重建数据不丢。

六、生产部署要点

不要用root用户跑容器，Dockerfile加USER node。镜像要打版本标签，不要用latest。日志输出到stdout/stderr让Docker收集。健康检查HEALTHCHECK。资源限制--memory、--cpus防止单个容器吃满机器。

七、常见坑

容器里进程监听127.0.0.1，外部访问不到。要监听0.0.0.0。容器重建数据丢失，数据库数据必须挂volume。镜像体积大，用alpine基础镜像加头阶段构建。

八、CI/CD里用Docker

代码push到GitHub后，CI自动构建镜像推到Registry，生产服务器pull新镜像重启。整个过程全自动，不用人登服务器。

九、Docker网络

容器间通信用Docker Compose服务名当域名。db容器名连接postgres://db:5432。不需要写IP，Docker内部DNS自动解析。

十、总结

Docker是现代部署标配。写好Dockerfile、用好层缓存、多阶段构建压缩体积、docker-compose管理多服务，一套标准流程把应用稳定部署到任何云服务器。
