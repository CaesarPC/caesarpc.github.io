Nginx实战：反向代理、负载均衡和缓存

CaesarTools 技术文章 · 2026-10-15

一、Nginx是网站大门

用户访问example.com，先到Nginx。Nginx决定：直接返回静态文件？转发给Node进程？转发给哪个Node实例？它单机能抗5万并发。

二、反向代理静态站点

server {

listen 80;

root /var/www/dist;

index index.html;

location / { try_files $uri $uri/ /index.html; }

}

SPA路由刷新404，try_files全部fallback到index.html。

三、反向代理后端

location /api/ {

proxy_pass http://127.0.0.1:3000;

proxy_set_header Host $host;

proxy_set_header X-Real-IP $remote_addr;

}

透传真实IP给后端。

四、负载均衡

upstream backend {

server 127.0.0.1:3000;

server 127.0.0.1:3001;

}

server { location / { proxy_pass http://backend; } }

多实例轮询。一个挂了自动踢掉。

五、HTTPS

listen 443 ssl;

ssl_certificate /etc/letsencrypt/live/.../fullchain.pem;

ssl_certificate_key ...;

80端口301跳HTTPS。

六、静态资源缓存

location ~* \.(js|css|png|jpg)$ {

expires 30d;

add_header Cache-Control "public";

}

七、常见坑

WebSocket要Upgrade头。

大文件上传client_max_body_size默认1MB，调大。

改配置nginx -t测试再reload。

后端拿到的是Nginx IP，要X-Forwarded-For透传。

八、访问日志

Nginx默认日志在/var/log/nginx/access.log。记录每个请求的IP、路径、状态码、耗时。排查问题先看日志。

九、总结

Nginx做反向代理、负载均衡、HTTPS终止、静态资源缓存。学会基础配置，网站才算真正上线。
