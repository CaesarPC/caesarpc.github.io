前端测试入门：单元测试、集成测试和E2E测试

CaesarTools 技术文章 · 2026-10-15 📅 2026-10-15

一、为什么要写测试

没有测试的代码，改一处不敢碰另一处。重构等于赌博。上线出bug只能靠用户反馈。测试是给代码上保险——改完跑一遍测试，知道没破坏旧功能。

二、测试金字塔

底层：单元测试，多而快，测单个函数。

中层：集成测试，少而稳，测模块间配合。

顶层：E2E测试，最少最慢，模拟用户操作。

越往上越慢越贵。大部分测试应该是单元测试。

三、单元测试

测单个函数，不依赖外部。用Vitest（Vite原生）或Jest。

function add(a, b) { return a + b; }

test('1+1=2', () => {

expect(add(1,1)).toBe(2);

});

覆盖正常情况、边界情况、异常情况。

四、组件测试

React组件用Testing Library渲染组件，模拟点击，断言输出。

import { render, screen, fireEvent } from '@testing-library/react';

test('点击按钮计数加一', () => {

render();

fireEvent.click(screen.getByText('+1'));

expect(screen.getByText('1')).toBeInTheDocument();

});

五、集成测试

测多个模块配合。比如登录流程：输入账号密码→调API→跳首页。API用MSW mock掉。

六、E2E测试

用Playwright或Cypress，真实浏览器模拟用户操作。打开网站、点击、输入、断言。慢但最接近真实。

七、覆盖率

覆盖率多少合适？80%是个参考线。不要为了覆盖率写无意义的测试。关键业务逻辑必须测。

八、CI里跑测试

push代码后GitHub Actions自动跑测试。挂了阻止合并。坏代码上不了main。

九、常见误区

坑1：不写测试。迟早还债。

坑2：测试实现细节不测行为。重构测试就挂。

坑3：E2E测试写太多。慢，维护成本高。

坑4：mock过度。什么都mock等于没测。

十、TDD测试驱动开发

先写测试再写代码。测试定义行为，代码让测试通过。好处是代码天然可测，设计更清晰。缺点是初期慢。

十一、总结

测试是工程成熟度标志。单元测试主力，组件测试补充，E2E测关键流程。CI里自动跑。写测试不优雅，但省未来无数次救火。
