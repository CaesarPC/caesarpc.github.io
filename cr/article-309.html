AI模型部署：vLLM和量化实战

CaesarTools 技术文章 · 2026-10-15

一、模型部署的挑战

训练好的模型是文件，用户没法用。部署就是包成API：发文字返回生成内容。推理吃GPU显存，并发要高。

二、基础方案

FastAPI + transformers：

@app.post("/generate")

def generate(prompt: str):

return model.generate(prompt)

简单但并发低，一个请求推理其他排队。

三、vLLM高并发

7B模型原生transformers每秒几个请求。vLLM用PagedAttention，吞吐量提升10-20倍，显存利用率从20%到90%。

python -m vllm.entrypoints.openai.api_server --model Qwen/Qwen2-7B

直接暴露OpenAI兼容接口。

四、量化

7B FP16要14GB显存。INT4只要4GB，一张4090跑。

BitsAndBytesConfig(load_in_4bit=True)。精度略降，多数场景无感。

五、GPU选择

7B INT4：RTX 4090 24GB。

7B FP16：A10G 24GB。

70B INT4：A100 80GB。

六、常见坑

模型加载慢，启动后预热。

显存OOM，限制max_tokens。

并发低，用vLLM。

同步阻塞，用FastAPI异步。

七、和业务后端配合

AI服务独立部署GPU机器，业务后端HTTP调用。不要塞一个进程。

八、监控

GPU利用率、显存、推理延迟P99。低于30%浪费钱，高于90%加卡。

九、模型版本管理

多个版本模型，用环境变量MODEL_VERSION切换权重。A/B测试同时跑两个版本，按流量比例分流。

十、总结

AI部署选vLLM、做量化、独立部署、监控GPU。个人4090跑7B，企业A100跑70B。
