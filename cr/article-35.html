TypeScript从入门到实战

CaesarTools 技术文章 · 2026-10-15 📅 2026-10-15

一、为什么要用TypeScript

JavaScript是动态类型语言，没有编译期检查。你写了一个函数，传参时传错类型，代码跑到一半才报undefined is not a function。而且编辑器没有类型提示，打一半不知道对象有哪些属性，全靠记忆和文档。

TypeScript在JS之上加了一层静态类型系统。写代码时编辑器实时告诉你这里应该传什么类型，编译时把所有类型错误抓出来，最后编译成普通JS跑在浏览器和Node上。2024年React和Vue官方新项目默认用TS，大型公司招前端JD上基本都要求TS。学它不是选择题，是必做题。

二、基本类型注解

let name: string = "小明";

let age: number = 12;

let isActive: boolean = true;

let hobbies: string[] = ["投球", "笛子"];

let nothing: null = null;

联合类型表示一个值可以是几种类型之一：

let id: string | number;

id = "abc";

id = 123;

类型别名：

type ID = string | number;

let uid: ID;

三、接口和类型

interface User {

id: number;

name: string;

email?: string; // 可选属性

readonly createdAt: Date; // 只读

}

function createUser(name: string): User {

return {

id: 1,

name,

createdAt: new Date()

};

}

interface可以扩展：

interface Admin extends User {

permissions: string[];

}

type和interface区别：type能定义联合类型和交叉类型，interface能继承和声明合并。实际项目大部分场景两个都行。

四、函数类型

函数参数和返回值都要标类型：

function add(a: number, b: number): number {

return a + b;

}

函数类型本身：

type AddFn = (a: number, b: number) => number;

回调函数：

function fetchUser(id: number, callback: (user: User) => void): void {

// ...

}

五、泛型

泛型让函数可以处理多种类型同时保持类型安全：

function first(arr: T[]): T | undefined {

return arr[0];

}

const n = first([1, 2, 3]); // n是number

泛型在React的useState、API响应数据里到处用：

const [user, setUser] = useState(null);

六、从JS迁移到TS

老项目迁移不要一步到位。分步骤：先tsc --init开strict，把新写的模块用TS，老JS文件保留。用// @ts-check在JS文件里获得类型提示渐进迁移。不要一上来就写any，any等于没写类型。

七、常见坑

坑1：滥用any。一时爽，类型检查形同虚设。用unknown代替，它是类型安全的any。

坑2：类型断言as。先判断再断言，不要直接as User。

坑3：开了strictNullChecks，所有可能为null的值要写判空。

坑4：第三方库没类型声明，装@types/xxx，或者自己写d.ts。

八、工具类型

Partial所有属性变可选。

Required所有属性必填。

Pick选几个属性。

Omit排除某个属性。

九、总结

TS是JS的超集，加了静态类型。从基本类型、接口、函数、泛型开始学，开strict模式，渐进迁移老项目。它会让你写代码慢一点，但bug少一半，长期省时间。
