前端状态管理：从useState到Redux/Zustand

CaesarTools 技术文章 · 2026-10-15

一、状态为什么会乱

组件多了，状态到处放。A组件的状态B组件要用，C组件改了D组件不知道。prop一层层传（prop drilling），代码又臭又长。

状态管理库就是把共享状态提到外面，任何组件直接读写。

二、React内置方案

useState管组件本地状态。useContext跨层级传状态。

简单场景够用。复杂场景要外部库。

三、Redux

单向数据流：action→reducer→state→view。可预测，好调试。Redux DevTools时光旅行。

但样板代码多，新手劝退。现代Redux Toolkit简化了。

四、Zustand

极简：const useStore = create((set) => ({ count: 0, inc: () => set(s => ({count: s.count+1})) }))。组件直接useStore()。

API简单，体积小，2024年新项目推荐。

五、TanStack Query

服务器状态单独管。缓存、后台刷新、失败重试。不要把服务器数据塞Redux。

useQuery({ queryKey:['users'], queryFn:fetchUsers })。自动缓存，第二次读秒开。

六、什么时候用什么

- 组件本地状态：useState

- 跨层级主题/用户：useContext

- 复杂客户端状态：Zustand

- 服务器数据：TanStack Query

- 大型企业项目：Redux Toolkit

七、常见坑

坑1：所有状态塞一个store。拆成多个store。

坑2：服务器数据塞客户端store。用TanStack Query。

坑3：状态更新不规范。直接改state，视图不更新。

坑4：过度使用。小项目不需要状态库。

八、状态和请求的关系

客户端状态（UI开关、表单草稿）和服务器状态（用户数据、列表）要分开管。TanStack Query管服务器状态，Zustand管客户端状态。混在一起调试噩梦。

九、总结

状态管理按场景选。本地用useState，跨层级用Context，复杂客户端用Zustand，服务器数据用TanStack Query。不要为了用库而用库。
