Vite前端构建工具详解

CaesarTools 技术文章 · 2026-10-15 📅 2026-10-15

一、Webpack为什么慢

中型项目冷启动30秒，改一行等5秒。Webpack启动时递归打包所有模块，不管你用不用。每次改代码都要重新打包整个项目，文件多了就慢得要命。

Vite利用浏览器原生ESM和esbuild，启动300毫秒。

二、Vite为什么快

开发时不打包。浏览器请求哪个文件才处理哪个。项目从100模块变10000，启动时间不变。

esbuild预构建依赖，比JS打包器快10-100倍。

改一个文件只重新请求那个模块，毫秒级HMR。

三、基本使用

npm create vite@latest my-app -- --template react

cd my-app && npm install && npm run dev

四、生产构建

npm run build用Rollup。代码压缩、tree-shaking、分包。

五、常用配置

server.proxy开发代理。

build.rollupOptions.output.manualChunks分包。

import.meta.env.VITE_xxx环境变量。

六、插件生态

@vitejs/plugin-react、plugin-vue。社区插件丰富。

七、常见坑

IE不支持ESM用legacy插件。

老项目迁移成本高。

某些Webpack loader要换Vite插件。

八、Vite和Webpack怎么选

新项目Vite。老项目Webpack迁移成本高，逐步迁。需要兼容IE11用Webpack或Vite legacy插件。

九、总结

Vite用浏览器原生能力重新定义开发体验。启动快、HMR快、配置简单。新项目无脑选。
