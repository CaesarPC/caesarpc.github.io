HTTPS与网站安全实战

CaesarTools 技术文章 · 2026-10-15

一、为什么必须上HTTPS

HTTP是明文传输，你登录网站输入的密码，中间经过的每一个路由器都能看到。2024年Chrome和Firefox对所有HTTP网站直接标"不安全"红色警告，搜索引擎也把HTTPS作为排名信号，支付接口和Cookie的Secure属性更是强制要求HTTPS。不上HTTPS基本等于没法做正经网站。

二、免费SSL证书怎么申请

Let's Encrypt提供完全免费的SSL证书，三个月有效期，自动续期。用Certbot工具一键配置：

sudo certbot --nginx -d example.com -d www.example.com

Certbot会自动改Nginx配置文件，自动申请证书，自动配置HTTPS跳转。跑完就能用。三个月后它自己会续期，不用人管。

三、OWASP十大安全风险要防什么

3.1 SQL注入

用户输入直接拼SQL字符串："SELECT * FROM users WHERE id = " + req.query.id。攻击者传id=1;DROP TABLE users;，你的库就没了。解法永远是参数化查询：pool.query('SELECT * FROM users WHERE id = $1', [id])。

3.2 XSS跨站脚本

用户评论里写，其他用户访问时脚本就在浏览器里跑了。解法：输出到HTML时转义特殊字符。React默认转义，v-html要特别小心。CSP响应头限制脚本来源。

3.3 CSRF跨站请求伪造

用户登录你的网站，同时访问恶意网站，恶意网站偷偷发请求到你的后端，带着用户Cookie。解法：CSRF Token、SameSite Cookie、验证Referer头。

3.4 敏感数据泄露

密码绝对不能明文存数据库。用bcrypt哈希，bcrypt自带salt，计算慢，抗暴力破解。数据库被拖库，攻击者拿到的也是哈希值。

四、安全响应头

Nginx配置加几个头，挡住大部分攻击：

add_header X-Frame-Options DENY;

add_header X-Content-Type-Options nosniff;

add_header Strict-Transport-Security "max-age=31536000";

add_header Content-Security-Policy "default-src 'self'";

X-Frame-Options防止别人iframe嵌套你的页面做点击劫持。HSTS强制浏览器以后都用HTTPS访问。CSP限制脚本只能从自己域名加载。

五、CORS跨域配置

不要直接写Access-Control-Allow-Origin: *。生产环境指定具体域名：

app.use(cors({

origin: 'https://example.com',

credentials: true

}));

六、密钥管理

数据库密码、JWT密钥、第三方API Key不要写代码里。用环境变量：

DATABASE_URL=postgres://...

JWT_SECRET=随机长字符串

.gitignore文件要把.env排除。一旦密钥提交到GitHub公开仓库，立刻删、换密钥、改历史。

七、登录接口防护

登录是攻击重灾区。加三道防线：失败5次锁账号10分钟；图形验证码或滑块防爆破；日志记录异常IP，批量失败的IP直接封。JWT有效期设15分钟，泄露了影响也小。

八、依赖安全

npm audit扫描已知漏洞。重要项目用lock文件锁版本。GitHub Dependabot自动提PR修依赖漏洞。

九、常见漏项

后台管理地址/admin不做IP白名单，被爆破。上传接口不校验文件类型，传个webshell上去。错误信息把堆栈返回给用户，泄露数据库结构。日志里打印密码。这些都是新手常犯的错。

十、总结

网站安全不是一次配置就完事。HTTPS是基础，SQL注入/XSS/CSRF要从代码层防，密码哈希、密钥管理、安全响应头、CORS配置一套配齐。安全是持续工程，不是一次性项目。
