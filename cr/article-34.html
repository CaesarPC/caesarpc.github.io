CSS动画性能：让页面60帧丝滑

CaesarTools 技术文章 · 2026-10-15

一、为什么动画会卡

屏幕每秒刷新60次，每帧16.7毫秒。一帧里浏览器要做Layout、Paint、Composite。超过16毫秒就掉帧。

动画改width/left，每帧都触发Layout+Paint，手机上必卡。改transform/opacity，只触发Composite，GPU加速，60帧丝滑。

二、触发浏览器工作的属性

Layout（重排）：width、height、margin、padding、left、top、position、font-size。

Paint（重绘）：color、background、border、box-shadow、outline。

Composite（合成）：transform、opacity。

动画只用transform和opacity。

三、transform

transform: translate/scale/rotate/skew。不影响布局，GPU合成。

@keyframes slide {

from { transform: translateX(-100%); }

to { transform: translateX(0); }

}

四、will-change

提前告诉浏览器这个元素要动画，浏览器提前优化：

.will-animate { will-change: transform; }

不要滥用，每个will-change占额外显存。

五、requestAnimationFrame

JS动画用requestAnimationFrame，跟着浏览器刷新节奏。setInterval不准，可能掉帧。

function animate() {

element.style.transform = `translateX(${x}px)`;

requestAnimationFrame(animate);

}

六、长列表滚动

大数据列表不要全部渲染。虚拟滚动：只渲染可视区域，滚动时动态替换内容。

七、图片懒加载

原生懒加载。图片进视口才下载。首屏加载快。

八、常见坑

坑1：动画改left/width，掉帧。

坑2：will-change到处加，显存爆。

坑3：阴影+动画同时，Paint太贵。

坑4：同时太多动画，主线程忙不过来。

九、DevTools检查

Performance面板录一次动画。紫色块是Paint，太长就是Paint开销大。绿色块Layout。FPS Meter看帧率。

十、硬件加速

transform和opacity会让浏览器给元素单独开一个GPU图层。过多图层反而增加合成开销。只有需要动画的元素才开。

十一、总结

CSS动画性能核心：只动transform/opacity，GPU合成。JS动画用requestAnimationFrame。虚拟滚动处理长列表。做好这几点，动画丝滑不卡。
