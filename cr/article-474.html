CSS动画与过渡实战

CaesarTools 技术文章 · 2026-10-15 📅 2026-10-15

一、transition过渡

属性变化时平滑过渡：

.button { transition: background 0.3s ease; }

.button:hover { background: blue; }

不要写all，指定属性性能好。

二、@keyframes动画

@keyframes slide {

from { transform: translateX(-100%); }

to { transform: translateX(0); }

}

.animate { animation: slide 0.5s ease; }

三、性能原则

动画只动transform和opacity。GPU合成，不触发Layout和Paint。

动left/width每帧重排，掉帧。

四、will-change

提前告诉浏览器这个元素要动画：

.will-animate { will-change: transform; }

不要滥用，占额外显存。

五、requestAnimationFrame

JS动画跟着浏览器刷新节奏。setInterval不准。

function animate() {

el.style.transform = `translateX(${x}px)`;

requestAnimationFrame(animate);

}

六、常见坑

坑1：动画改left/width掉帧。

坑2：will-change到处加显存爆。

坑3：阴影+动画同时Paint太贵。

坑4：同时太多动画主线程忙。

七、DevTools检查

Performance面板录动画。紫色Paint太长。FPS Meter看帧率。

八、硬件加速

transform和opacity让浏览器给元素单独开GPU图层。过多图层增加合成开销。只有需要动画的元素才开。

九、总结

CSS动画性能核心：只动transform/opacity，GPU合成。JS用requestAnimationFrame。
