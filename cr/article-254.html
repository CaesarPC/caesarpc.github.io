Redis缓存实战：让数据库抗住10倍流量

CaesarTools 技术文章 · 2026-10-15

一、Redis是什么

数据放内存，读0.1毫秒。单线程，单机每秒10万读写。最常见用法是缓存热点数据。

二、基本用法

const redis = require('redis');

const client = redis.createClient();

await client.connect();

await client.setex('article:list', 10, JSON.stringify(articles));

const cached = await client.get('article:list');

三、缓存流程

先查缓存，没有查数据库，查完写回缓存。

四、三大问题

穿透：查不存在的key。缓存空结果或布隆过滤器。

击穿：热点key过期。互斥锁或不过期。

雪崩：大量key同时过期。TTL加随机偏移。

五、更新策略

先更新数据库，再删缓存。不要先更新缓存。

六、其他用途

排行榜用ZSet。分布式锁SET NX。消息队列用List/Stream。

七、常见坑

坑1：大key。拆分小key。

坑2：没TTL，内存撑爆。

坑3：公网暴露。开密码绑内网。

坑4：当数据库用。缓存要能从数据库重建。

八、生产部署

开requirepass密码、绑定内网IP、RDB+AOF持久化、内存满了配allkeys-lru淘汰。主从复制+哨兵做高可用。

九、总结

Redis缓存热点数据抗压力。处理好穿透、击穿、雪崩。生产开密码、持久化、主从高可用。
