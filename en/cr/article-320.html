Git团队协作规范

CaesarTools Tech Articles · 2026-10-15

一、Git为什么重要

多人协作没有版本控制就是灾难。Git分布式，每台电脑完整历史，离线也能Submit。

二、分支工作流

main永远可部署。新功能开feature分支。开发完发PR，Review后合并。不直接push main。

三、Submit信息

feat新功能、fix修bug、docs文档、refactor重构。写清楚做了什么，不要写"更新"。

四、冲突解决

两人改同一行，手动保留正确部分，删标记，add再commit。预防：小步Submit、经常pull。

五、撤销操作

git checkout -- file撤销修改。

git reset HEAD fileCancel暂存。

git revert abc安全撤销。

git reset --hard强制回退（危险）。

六、暂存

git stash收起来，切分支干别的，pop恢复。

七、.gitignore

node_modules、.env、dist不Submit。

八、常见坑

大文件不要git add。用LFS。

密钥Submit到公开仓库，立刻换。

force push共享分支。

九、代码Review

PR不是走形式。看逻辑、测试、命名。被Review不要觉得被针对。

十、回滚

git revert坏Submit，push，自动重新部署。

十一、变基vs合并

main更新了，feature分支同步：merge产生合并Submit，历史分叉。rebase把Submit挪到main后，历史直线。rebase历史干净，但不要在共享分支用。

十二、总结

Git是工程师基本功。分支工作流、规范Submit、冲突解决、PR Review。工具简单，难在习惯。
