前端路由：Hash和History模式

CaesarTools Tech Articles · 2026-10-15

一、SPA路由原理

单页应用只有一个HTML。切换页面不刷新浏览器，JS根据URL渲染不同组件。路由就是URL和组件的映射。

二、Hash模式

URL长example.com/#/user/1。#后部分改了浏览器不刷新。监听hashchange事件。

优点：不用服务器配置。缺点：URL带#丑。

三、History模式

URL长example.com/user/1，没有#。用History API pushState改URL不刷新。

缺点：刷新页面404。服务器要配try_files fallback到index.html。

五、路由懒加载

const User = React.lazy(() => import('./User'));

访问/user才加载User的JS。首屏体积减小。

六、路由守卫

没Login踢回Login页。RequireAuth组件包裹。

七、常见坑

History模式刷新404，Nginx没配try_files。

懒加载白屏，加Suspense。

路由切换不滚到顶部，手动scrollTo。

八、SSR和SSG

SPA首屏慢、SEO差。Next.js服务器渲染HTML，首屏秒开，SEO友好。静态内容SSG，动态内容SSR。

九、总结

Hash简单，History好看。懒加载优化首屏，守卫做权限。理解原理，React Router/Vue Router都一样。
