CI/CD自动化部署实战

CaesarTools Tech Articles · 2026-10-15

一、手动发布的痛

git pull→npm install→build→scp上传→ssh重启。15分钟，容易出错，半夜爬起来。

CI/CD全自动：push代码→测试→构建→部署。

二、GitHub Actions

.github/workflows/deploy.yml：

on:

push:

branches: [main]

jobs:

deploy:

runs-on: ubuntu-latest

steps:

- uses: actions/checkout@v4

- run: npm ci

- run: npm test

- run: npm run build

- run: scp -r dist user@server:/var/www

三、Secrets

SSH密钥存GitHub Secrets，用${{ secrets.XXX }}引用。不写代码里。

四、测试是关键

CI不跑测试等于没CI。测试挂了阻止部署。

五、回滚

git revert坏Submit，push，自动重新部署。

六、常见坑

CI环境和生产不一致用Docker。

secrets硬编码立刻换。

直接部署生产先预发布。

七、蓝绿和灰度

零停机跑两个版本，Nginx切流量。灰度先给1%用户看。

八、主流工具

GitHub Actions：GitHub仓库直接用，小项目免费。GitLab CI：GitLab自带。Jenkins：自建，灵活但要维护。小项目无脑GitHub Actions。

九、总结

CI/CD是工程成熟度标志。GitHub Actions半小时搭好，告别手动发布。
